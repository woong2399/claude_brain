## 대화 흐름
1. 사용자: "시트에 11월 2일 뉴스가 안 들어왔어 넣어줘". 시트 A열을 읽어 11/01(179)·11/03·11/04 만 있고 11/02 가 없음을 확인. DB 에는 11/02 411건. 수집 프로그램(`python run_news.py`, 오후 1:39 시작)은 이미 끝나 있었다. `run_news.py --from 2026-11-02 --yes` → "411건 추가, 건너뜀 0건", 맨 끝에 붙음.
2. 정렬: 181행 이후 H~Z열이 비어 있음을 확인(정렬하면 X 표시와 어긋날 수 있어서) → `sortRange` 로 181~1486행만 A열(날짜), B열(시각) 오름차순. 경계 행을 읽어 확인: 11/02 181~591, 11/03 592~1036, 11/04 1037~1486, 177행의 사용자 의견도 그대로. 필터 범위를 1486행·A~J열로 확대.
3. 사용자: "아까 X 표시하고 의견 다는 걸 코드로 할 수 있어?" → 분류·제목 머리말 규칙을 11/01 의 Claude 판단(69건)과 비교(정밀도 77%, 재현율 68%). 규칙의 과다 표시는 사용자가 살리자고 한 기사들. 이유 칸은 정해진 문장밖에 못 씀, J열 의견은 사용자가 직접 다는 것. 방식 3가지 제시: ①규칙 1차 + 애매한 건 Claude 검토(추천) ②규칙만 ③코드에서 AI API(키·비용 필요).
4. 사용자: "1번" → `classify.py` 작성, 사용자 결정(속보, 교정시설 등)을 KEEP 에 반영해 11/01 비교: 정밀도 98%, 재현율 57%. 남은 과다 1건(`책` 분류의 웹툰 시장)은 `책` 을 규칙에서 뺌. `sheets.mark()`, `apps_script.gs` 의 `marks`, `run_news.py` 연결, README 갱신. 가짜 서버로 표시 요청·"옛 버전 응답" 처리 확인.
5. 사용자: "이 뉴스 배치파일은 뉴스 수집이잖아, 뉴스 검토도 배치파일 줘" → `review_news.py`/`.bat` (수집 제외, X 표시 + 키워드·테마 요약). "뉴스 검토"를 이렇게 해석했다고 알림.
6. 사용자(중간 메시지): "적절하지 않은 뉴스만 X 하도록" → 11/02~11/04 에서 X 안 달린 기사의 분류를 훑어 확실히 무관한 분류만 추가, 주식 단어 보호 유지. 11/02 요약의 `김희선` 16건은 연예 기사가 아니라 기자 이름 → 키워드 집계에서 제거.
7. 사용자: "기록해줘" → 이 노트.

## 구현 메모
- `apps_script.gs` `marks(sh, items)`: 시트 A..I 를 읽어 H 또는 I 에 값이 있는 **날짜** 집합을 만들고, 링크(G열)로 행을 찾아 그 날짜가 아니고 H·I 가 비어 있는 행에만 `[X, 이유]` 를 씀. 쓸 때는 H:I 블록 전체를 다시 씀(기존 값 유지).
- `sheets.mark()`: 500건씩 POST. 응답이 JSON 이 아니면(옛 버전 Apps Script) "새 버전으로 다시 배포해 주세요" 오류.
- `review_news.py`: 무관 기사(자동 X)를 뺀 나머지로 키워드(`min_count=3`, 상위 30)·테마(15개 규칙) 집계 → `data\review\review-날짜.md`, 여러 날짜면 `review-시작_끝.md` 도. `--no-sheet`, `--yes`, `--from/--to` 지원. 대화형일 때만 폴더를 연다.
- 키워드 집계 버그: 요약 끝에 "OOO 기자, 분야" 가 붙어 기자 이름이 반복 키워드로 잡힘 → `_BYLINE` 정규식으로 제거. 단독 조사 `으로` 도 불용어에 추가.
- 새 분류로 새로 X 가 된 기사 26건(11/02~11/04)을 눈으로 확인: 여행·연예(싸이커스, 리센느, 재혼황후, 탑, 김혜수, 전지윤)·날씨·스포츠(kt 한국시리즈, 저스티스 런, 큐엠아이티)·패션 뿐.
