# 2026-11-03 Storage — 수집 방식 변경 (상세)

요약: [[2026-11-03-수집방식변경]]

## 대화 흐름
1. 사용자가 "claude_brain 열어줘" → Brain 프로젝트(이름 바뀜)를 열어 상태 요약. 이어서 "storage 열어줘" → Storage 요약.
2. 사용자 요청: "15:30 정규장 마감이니 16:00 에 정규장 데이터까지 수집, 20:00 마감 데이터는 21:00 에 수집, 수집이 끝나면 컴퓨터는 끄지 않는 걸로."
3. 코드를 읽고 고침 → 테스트 통과 → "작업 스케줄러에 등록할까?" 질문.
4. 사용자: "작업 스케줄러는 만들어만 놓고 작동 중지로 해놔" → 새 작업 2개 등록 후 '사용 안 함'. 기존 작업은 지우지 않음.
5. 내가 알린 문제: 기존 20:30 작업은 바뀐 `run_update.bat` 을 그대로 부르므로 그날 밤엔 수집 후 PC 가 안 꺼진다.
6. 사용자: "일단 작업 스케줄러 다 꺼놔주고, 정규장 bat·이후 bat 이 뭐야?" → 4개 모두 '사용 안 함'. bat 은 하나(`run_update.bat`)이고 인자 `1600`/`2100` 으로 나눈다고 답함.
7. 사용자가 "1600 은 정규장, 2100 은 이후로 알면 되지?" / "시간이 늦어질 수도 있잖아" 라고 물음 → slot 은 이름표이고 실행 시각이 범위를 정하지만, KRX_REG 는 09:00~15:30 분봉만 쓰니 1600 을 늦게 돌려도 해가 없다고 설명. (처음 답에서 "시각에 맞춰 돌려야 한다"고 해서 헷갈리게 했다가 바로잡음.) 주의할 것은 2100 을 20:00 전에 돌리지 않는 것뿐(애프터마켓 덜 들어간 채 월말 백업).
8. 사용자: "지금 1600 돌려줘" → 16:51 백그라운드 실행. 처음 몇 초간 로그가 비어 있었음(100종목마다 한 줄 남기는 방식). 16:56 `진행 100/2674 (실패 0)`.

## 조사한 것 (코드)
- 작업 스케줄러 → `scripts\run_update.bat` → `python -m woong_stock update` → 성공하면 `scripts\after_update.ps1` (cloud-export → cloud_upload.py → 월말 backup.ps1 → 알림 → `shutdown /s /t 120`).
- `jobs.run_update`: 휴장 확인(삼성전자 일봉에 오늘이 있나) → 종목 갱신 → `db.for_each_code(con, f"update:{today}", ...)` → KRX_REG 재생성 → 시가총액 → 수정주가 이벤트 → 검증.
- **문제점 발견:** `for_each_code` 는 같은 job 이름에서 'done' 인 종목을 건너뛴다(이어받기). job 이름이 날짜뿐이라 같은 날 두 번째 실행은 아무것도 안 받는다.
- `minute.update_minutes`: 마지막 저장일부터 오늘까지, **마지막 날도 다시 받는다** ("일찍 실행돼 덜 받은 날을 메우기 위해") → 21:00 실행이 16:00 에 받은 날을 다시 채운다. 고칠 필요 없음.
- `daily.update_stock`: 수정주가 변경 판정에서 `fetched_at::DATE > date` 인 행만 비교 → 장중(같은 날)에 저장된 종가는 비교하지 않음 → 16:00 에 저장한 덜 확정된 KRX 일봉 때문에 가짜 권리 이벤트가 생기지 않는다. 고칠 필요 없음.
- `minute.build_krx_reg`: 분봉 09:00~15:30 으로 정규장 일봉을 만든다 → 16:00 이후 언제 돌려도 같은 결과.

## 고친 내용
- `__main__.py`: `update` 를 따로 만들고 `--slot` 인자(기본 빈 값). 빈 값이면 예전 job 이름 그대로.
- `jobs.py`: `run_update(..., slot="")`, job 이름 `update:YYYYMMDD` + `:slot`, 시작 알림에 `(slot)`.
- `run_update.bat`: `%1` 을 SLOT 으로, 없으면 2100. `update --slot %SLOT%`. 2100 이면 `after_update.ps1 -Final`.
- `after_update.ps1`: `param([switch]$Final)`, 백업은 `$Final` 일 때만, 종료 알림·`shutdown` 삭제.
- `register_task.ps1`: 예전 `woong_stock_update`·`woong_stock_weekend_off` 삭제 → `woong_stock_update_1600`(월~금 16:00, 인자 1600)·`woong_stock_update_2100`(월~금 21:00, 인자 2100) 등록. 설정은 예전과 같음(WakeToRun, StartWhenAvailable, 4시간 제한, 10분 간격 2번 재시도, 로그온한 경우에만).
- 주의: Write 로 다시 쓴 `register_task.ps1` 에서 UTF-8 BOM 이 빠져 다시 붙였다. Windows PowerShell 5.1 은 BOM 이 없으면 한글을 깨뜨린다.
- 검증: `.venv/Scripts/python.exe -m pytest -q` → `87 passed`.
