# 2026-11-04 Storage — KRX 시총 2010-01 확장 (상세)

요약: [[2026-11-04-KRX백필-2010확장]]

## 대화 흐름
1. 사용자 "총액은 2015-06 전 거는 못 받아?" → 최소 2010-01-04 까지 있음(앞선 시험에서 2010-01-04 925종목 응답, 2005-01-04 는 0건). 2010년부터 받을지 시작일을 먼저 찾을지 물음.
2. 사용자: "시가총액 가능한 한 제일 먼 과거부터 받아오자." → 시작일을 찾는 이진 탐색 스크립트를 임시 폴더에 만들어 실행.
3. 탐색 결과를 보고하는 중 사용자 메시지: "마찬가지로 코드로 돌려줘" → `backfill-krx --start 2010-01-01` 을 백그라운드로 실행 (직접 호출하지 않음).
4. 완료 알림이 왔지만 로그 끝에 `JSONDecodeError` → 중간에 멈춘 것을 확인하고 원인을 고쳐 이어받기.
5. 사용자: "back fill 끝났네, 확인하고 기록해줘."

## 탐색 (임시 스크립트 `krx_first_day.py`, 기록용 요약)
- 달력: 우리 DB 삼성전자 KRX 일봉 1985-01-04 ~ 2015-05-29 (8,157일). 단조(어느 날부터 있다)라고 가정하고 유가증권 응답 행 수가 0 보다 큰 첫 날을 이진 탐색.
- 결과: 데이터 없는 마지막 날 **2009-12-30**, 있는 첫 날 **2010-01-04**. 코스닥 2010-01-04 응답 1,036행. 탐색 호출 15건. 2010-01-04 ~ 2015-05 말 거래일 1,339일 → 호출 약 2,678건.
- 키 사용: `storage.config.load_env()` 로 읽고 헤더로만 보냄. 출력에 키는 없다.

## 실행과 오류
- 명령: `python -m storage backfill-krx --start 2010-01-01` (PowerShell 이 아닌 Git Bash 에서 `.venv\Scripts\python.exe`, 백그라운드).
- 1차: 10:08 시작 → 10:37 종료. 출력 끝:
  ```
  File ...\Lib\json\decoder.py, line 363, in raw_decode
      raise JSONDecodeError("Expecting value", s, err.value) from None
  json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0)
  ```
  종료 코드는 0 으로 보였지만(`tail` 의 코드) 실제로는 예외로 끝났다. 그날 저장된 것: `krx_daily` 3,585일(2,804 + 781), 수집 기록 `done` 3,585.
- 원인: `http_get` 이 `json.loads(...)` 를 그대로 호출 → 빈 본문(`char 0`)에서 `ValueError`(JSONDecodeError)가 올라가 `fetch_day` 의 `OSError` 처리를 지나쳐 전체가 종료. HTTP 상태는 200 이었다.
- 수정 (`storage/krx.py`):
  - `http_get`: JSON 으로 읽히지 않으면 `(status, 본문 앞 200자)` 를 돌려준다.
  - `fetch_day`: 200 인데 dict 가 아니면 `status=None` 으로 보고 5xx 처럼 `sleep(2**attempt)` 후 재시도(최대 3번), 계속 그러면 `KrxError` → `backfill_krx` 가 그 날만 `failed` 로 기록하고 계속.
  - 테스트: `test_fetch_day_retries_non_json_body_then_fails_the_day_not_the_run`, `test_http_get_returns_text_for_non_json_body` 추가. `pytest -q` → `105 passed`.
- 2차(이어받기): 약 10:40 시작 → 10:52 종료. `2010-01-01 ~ 어제, 거래일 4143일 중 이번 실행 558일 완료, 호출 1116건, 실패 0일`. 로그에 재시도 경고는 없었다 (빈 응답이 다시 나오지 않았거나 재시도로 해결됐는지는 확인하지 않음).
- 호출 속도: 호출당 약 0.65초(558일·1,116호출이 약 12분).

## 검증 출력 (읽기 전용)
- `krx_daily`: 9,336,965행, 4,143일, 2010-01-04 ~ 2026-11-03, 종목코드 3,699개. KOSPI 3,817,319 / KOSDAQ 5,519,646.
- 빈 값: `krx_mktcap` 0, `krx_amount` 0, `krx_close` 0.
- 수집 기록: `done` 4,143, `failed` 0 (실패 기록 없음).
- 날짜 수: DB 달력(삼성전자 KRX 일봉, 2010-01-01~2026-11-03) 4,143일 = `krx_daily` 날짜 4,143일.
- 코드: 전체 3,699, `stocks` 에 없는 코드 1,024, 그중 마지막 날 < 2026-10-01 인 코드 921.
- 삼성전자: 2010-01-04 종가 809,000·시총 119,165,163,633,000, 2013-01-02 1,576,000·232,143,755,112,000, 2015-05-29 1,307,000·192,520,233,459,000, 2015-06-01 1,291,000·190,163,444,067,000 (모두 KOSPI).
- 참고: 이 종가는 원주가라 액면분할(2018년) 이전 값이 크다. 시총은 분할과 무관하게 연속.

## 시행착오
- 임시 스크립트를 프로젝트 밖(임시 폴더)에 두었더니 `ModuleNotFoundError: storage` → `PYTHONPATH=.` 를 주고 다시 실행.
- 백필 1차가 예외로 멈췄는데 완료 알림이 "exit code 0" 로 와서 로그 끝을 확인하고서야 알았다. 앞으로 완료 알림 뒤에는 로그 끝줄과 DB 를 확인한다.
- 오류를 방치한 채 끝났다고 보고하지 않고 원인·범위를 먼저 알린 뒤 고쳤다.

- 키 호출 누계(11-04, 대략): 2015-06 백필 5,603 + 11-03 재시도 2 + 시험 약 10 + 시작일 탐색 15 + 2010 확장 약 2,678(1차 781일 × 2 = 1,562 + 2차 1,116) ≈ 8,300건. 하루 한도(10,000건, 제3자 자료 기준 미확인) 오류는 나지 않았다.
