# 2026-11-03 Storage — 수집 방식 변경

상세: [[2026-11-03-수집방식변경-상세]]

## 한 줄 요약
평일 20:30 한 번 수집하고 PC를 끄던 방식을, **16:00(정규장) + 21:00(애프터마켓까지)** 두 번 수집하고 **PC는 끄지 않는** 방식으로 코드를 바꿨다. 작업 스케줄러는 새 작업만 만들어 두고 **전부 꺼 놓았다.** 16:51에 1600 수집을 손으로 돌렸다.

## 한 일
- `update` 명령에 `--slot` 추가 (예: `1600`, `2100`). 이어받기 기록 이름이 `update:YYYYMMDD:<slot>` 이 된다.
- `run_update.bat <slot>` 으로 실행. 값이 없으면 `2100`.
  - 1600: 수집 → MotherDuck 업로드
  - 2100: 수집 → MotherDuck 업로드 → 월말이면 G 드라이브 백업
  - 어느 쪽도 PC 를 끄지 않는다 (`after_update.ps1` 에서 `shutdown` 제거)
- `register_task.ps1`: 16:00·21:00 작업 2개 등록 + 예전 작업 2개 삭제로 바꿈.
- 작업 스케줄러: 새 작업 `woong_stock_update_1600`·`woong_stock_update_2100` 을 등록했고, 기존 `woong_stock_update`(20:30)·`woong_stock_weekend_off` 까지 **4개 모두 '사용 안 함'** (사용자 요청). 등록 스크립트는 돌리지 않고 같은 내용을 직접 실행했다 (예전 작업을 지우지 않으려고).
- 테스트 87개 통과.
- 2026-11-03 16:51 `run_update.bat 1600` 수동 실행. 16:56 100/2,674, 실패 0.

## 결정 (이유)
- **slot 으로 이어받기 기록을 나눔:** 예전엔 하루에 하나라서, 21:00 실행이 16:00 실행의 '완료' 기록을 보고 전 종목을 건너뛰었을 것이다.
- **slot 은 이름표일 뿐, 받는 범위는 실행 시각이 정한다.** 그래도 1600 을 늦게 돌려도 괜찮다: 정규장 일봉(KRX_REG)은 분봉 09:00~15:30 만 모아 만들고, 분봉은 마지막 저장일을 다시 받으니 2100 이 나머지를 채운다.
- **월말 백업은 2100 뒤에만:** 애프터마켓까지 다 들어간 뒤에 백업해야 한다. 그래서 2100 은 20:00 전에 돌리지 않는다.
- **PC 끄지 않음:** 사용자 요청. 그러면 BIOS 자동 켜짐과 주말 종료 작업이 필요 없다.
