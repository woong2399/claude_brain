# 2026-11-04 Storage — KRX 백필·추정 거래대금·수집 흐름

상세: [[2026-11-04-KRX백필-추정거래대금-상세]] · 같은 날 앞선 작업: [[2026-11-04-이름변경]] · **이후:** KRX 시총을 2010-01 까지 확장 → [[2026-11-04-KRX백필-2010확장]] (이 노트의 "2015-06 부터"·"2010 이전 미정"은 그 노트가 최신)

## 한 줄 요약
KRX 공식 Open API 로 **과거 시가총액**을 2015-06 부터 `krx_daily` 에 채웠고, 정규장 거래대금이 없는 문제는 **분봉 추정 칸 `daily_bar.amount_est`** 로 해결했다. 수집 흐름은 "1600 은 수집만, 2100 뒤에 업로드 한 번"으로 바꾸고, Surge 는 로컬 DuckDB 에서 읽어 CSV 만 만들게 했다.

## 한 일
- **KRX 키·서비스 승인:** `.env` 의 `KRX_API_KEY` 에 키를 넣었고(사용자), 유가증권·코스닥 일별매매정보 서비스 이용 신청이 승인된 뒤에 호출이 성공했다. 키만 있을 때는 401 "Unauthorized API Call" 이었다.
- **`backfill-krx` 명령** (`storage/krx.py`): 우리 DB 거래일마다 두 시장을 1회씩 호출해 `krx_daily` 에 넣는다. 이어받기(`collect_state` job `backfill-krx`), 호출 상한 8,000건, 401·429 에서 멈춤, 10% 마다 텔레그램 알림. 키는 헤더로만 보낸다.
- **결과:** 2015-06-01 ~ 2026-11-03, 거래일 2,804일, 약 673만 행(유가증권 258만·코스닥 415만). 시가총액·거래대금·종가가 빈 행 0. 호출 약 5,600건, 93분. 11-03 하루는 새벽에 빈 응답이라 실패했다가 08:17 에 다시 돌려 채웠다.
- **`daily_bar.amount_est` 칸:** 정규장(09:00~15:30) 분봉 (시가+고가+저가+종가)/4 × 거래량 합(백만 원). KRX_REG 행에만, 분봉이 있는 2025-10-01 ~ 11-03 (원주가 669,711행·수정주가 669,684행). 실제 `amount` 는 덮어쓰지 않았다. 정규장 일봉을 만들 때마다 자동으로 채운다.
- **수집 흐름 (`scripts\run_update.bat`):** 1600 은 수집만, 2100 은 수집 → MotherDuck 업로드(하루 한 번) → 월말 백업. KRX 는 매일 받지 않는다.
- **Surge (`C:\Users\Jinwo\Documents\surge\surge_daily.py`):** 로컬 DuckDB 를 읽기 전용으로 읽고(`.venv` 로 실행), 거래대금은 `amount_est`, MotherDuck `surge.picks` 에는 쓰지 않고 CSV 만 만든다. 11-02(48종목)·11-03(21종목) CSV 를 다시 만들었다.
- 테스트 103개 통과. 커밋 `342bb0d` push 완료 (프로그램 저장소).

## 알게 된 것
- **KRX 값의 의미:** 종가·시가총액은 정규장 종가 기준(시총 = 상장주식수 × 정규장 종가와 정확히 같음), 거래량·거래대금은 애프터마켓·시간외까지 합친 하루 전체 값이다. 삼성전자 10-30 거래대금 4,377,894백만 원이 우리 키움 일봉 값과 같다. **정규장만의 거래대금은 키움에도 KRX 에도 없다.**
- **키움 vs KRX 거래대금(2015-06 이후):** 같은 행 6,047,867, 다른 행 581 → 사실상 같다. 그래서 KRX 는 거래대금용이 아니라 **과거 시가총액**을 얻으려고 받은 것이다 (키움 시총은 11-02 부터만 있다).
- **KRX 데이터는 다음 날 아침에 올라온다:** 11-03 데이터가 11-04 01:45·03:18 에는 없고 08:17 에는 있었다. 올라오는 정확한 시각은 미확인.
- **애프터마켓 체결은 16:00 부터:** 분봉에 15:35 봉 하나가 있지만 실제 체결은 16:00 이후다. 삼성전자 11-03 15:30 이후 거래량 441,442주 중 17:00 이후가 88%. 그래서 1600 수집 중 받는 키움 일봉 거래대금에는 받는 시각까지의 애프터마켓이 종목마다 다르게 섞인다.
- **`amount_est` 정확도 (09-11 이전 실제 값과 비교, 58만 행):** 추정/실제 중앙값 0.998, ±5% 이내 96.2%, 평균 절대 오차 1.2%. 실제 값에 시간외·대량매매가 들어 있어 추정이 대체로 조금 작다. 칸에 저장한 뒤 다시 비교하면 중앙값 0.9999·±5% 이내 96.8% (백만 원 반올림 차이).
- **KRX 에만 있는 종목 625개**, 그중 522개는 마지막 날이 2026-10 이전 → 상장폐지 종목의 종가·거래량·거래대금·시총 기록이 있다 (시가·고가·저가는 저장하지 않았다).
- **DB 저장 방식:** 같은 키면 덮어쓰고 없으면 추가(INSERT OR REPLACE). 2100 도 1600 과 같은 `update` 라 정규장 데이터를 다시 받고 애프터마켓만 추가된다. 오래 걸리는 건 저장이 아니라 키움 호출(종목당 약 5번).

## 결정 (이유)
- **KRX 는 매일 받지 않는다:** 거래대금은 2100 키움 일봉과 같고, 시가총액은 `kiwoom_mktcap` 이 매일 같은 방식으로 쌓는다. 같은 값을 한 번 더 받을 이유가 없다. 필요하면 `backfill-krx` 를 손으로 돌린다.
- **MotherDuck 업로드는 2100 뒤 한 번만(통째로):** 증분 업로드는 만들지 않는다. 지금은 Colab 시뮬레이션을 안 쓰고 Surge 는 로컬을 읽으므로 `storage` DB 를 읽는 곳이 없다 → 업로드를 남길지는 사용자가 유지하기로 했고, MotherDuck `storage`·`surge` DB 는 그대로 둔다.
- **정규장 거래대금은 별도 칸 `amount_est`:** 정확한 값과 추정값을 섞지 않으려고. 09-11 이전은 `amount`(실제), 09-14 이후 정규장은 `amount_est`.
- **애프터마켓 추정 거래대금은 만들지 않는다:** 필요할 때 `minute_bar_amount` 뷰로 시간대를 골라 합한다.
- **Surge:** 로컬 DuckDB 읽기, 거래대금 `amount_est`, CSV 만. Daily 는 MotherDuck 대신 CSV 를 읽는다 (Daily 쪽 변경은 나중에).
- **작업 방식:** 대량 호출은 Claude 가 직접 하지 않고 명령(코드)으로 돌린다 (토큰 소모). 사용자가 확인하지 않은 수정은 하지 않는다. → [[사용자]]
