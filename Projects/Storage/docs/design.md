# storage 설계서

> 상태: **결정 완료, 사용자 검토 대기** · 최종 수정: 2026-10-30
> 코딩은 아직 시작하지 않았습니다. 이 문서를 승인하면 구현 계획을 세웁니다.

---

## 1. 한 줄 요약

키움증권 **REST API**로 국내 주식 데이터를 **과거 전부 + 매일** 수집해서, 나중에 만들 **시뮬레이터(백테스트)** 의 데이터 원천으로 쓴다.

## 2. 왜 새로 만드나

- 지금 쓰는 키움 **Open API(OCX)** 수집기(`storage_openapi`)는 오류가 잦고 조회 횟수 제한이 심하다.
  - 0.5초 간격이면 약 5,000번째 요청에서 조회 제한(-200)에 걸려, 지금은 3.6초 간격(시간당 1,000회)으로 돌리고 있다.
- REST는 HTTP 요청이라 32비트 Python, OCX, 로그인 창이 필요 없고, 무인 운영과 재시도가 쉽다.
- 주의: REST도 TR별로 초당 약 1회라는 블로그 실측이 있다(공식 수치는 아님). **순간 속도보다 "끊기지 않고 무인으로 도는 것"이 목적**이다.

## 3. 결정 사항

| # | 주제 | 결정 |
|---|---|---|
| 1 | 바뀌는 IP | 수집 시작 전 공인 IP를 확인한다. 바뀌었거나 IP 인증 오류가 나면 **수집을 멈추고 텔레그램으로 "새 IP 등록 필요"** 를 보낸다. 사용자가 키움 포털에 등록하면(최대 10개) 다음 실행 때 멈춘 지점부터 이어받는다. 유료 고정 IP는 쓰지 않는다. |
| 2 | 수정주가 | **원주가와 수정주가를 둘 다 저장**한다. 매일 최근 며칠치 수정주가를 다시 받아 저장값과 비교하고, 다르면(권리 이벤트) 그 종목의 전체 이력을 다시 받고 「지표 재계산 필요」 표시를 남긴다. |
| 3 | 수집 종목 | **코스피·코스닥의 보통주 + 우선주만** 받는다. ETF, ETN, 스팩, 리츠, 인프라·선박펀드, 코넥스는 제외한다. 코스닥 외국기업(15개)은 **포함**하고 `stocks.foreign`으로 표시한다. |
| 4 | 로그·오류 | ① 날짜별 파일 로그 ② DB의 **수집 상태 테이블**(종목별 진행 상황, 이어받기용) ③ 수집 후 **자동 검증 리포트**(이상값, 누락일) |
| 5 | 알림 | **텔레그램 봇**으로 보낸다. 카카오톡은 기존 수집기에서 알림이 오지 않았다. 알림 시점은 시작, 진행률 25%마다, 오류(즉시), IP 변경, 완료 요약, 하루 한 번 정상 종료 보고다. |
| 6 | 저장 | **DuckDB 파일 하나** (`storage.duckdb`) |
| 7 | 기존 Open API 데이터 | **REST로 전부 새로 받는다.** 기존 데이터는 교차검증 기준으로만 쓰고 DB에 가져오지 않는다(#12). Open API 수집기는 REST가 안정되면 끈다. |
| 8 | KRX / 통합 시세 | 일봉을 `venue`로 구분해 **세 가지 모두 저장**한다. 시뮬레이터가 어느 종가를 기본으로 쓸지는 시뮬레이터를 만들 때 정한다.<br>• `KRX`: 키움 KRX 일봉 그대로. **영웅문의 KRX 종가와 같다**(2026-10-30 삼성전자 220,500으로 확인). 2026-09-14부터는 애프터마켓 마지막 가격이다.<br>• `KRX_REG`: KRX 정규장(09:00~15:30). 2026-09-11까지는 `KRX`와 같고, 2026-09-14부터는 KRX 분봉으로 만든다.<br>• `AL`: 키움 통합 시세 (2025-03 이후) |
| 9 | 지표 | 수집하지 않는다. **나중에 계산해서 DB의 별도 테이블에 저장**한다(가격 테이블과 분리). |
| 10 | 수집 단위 | **일봉**: 과거 전체를 백필하고 매일 갱신한다. **분봉(KRX)**: **2025-10부터 지금까지 전부** 받고, 이후 매일 갱신한다. **2025년 10월분을 먼저** 받아 기존 Open API 분봉과 대조하고, 나머지 달은 순서 상관없이 받는다. 2026-09-14 이후 분봉으로 `KRX_REG`를 만든다(#8). |
| 11 | 매일 수집 시각 | **20:30** (KRX·NXT 애프터마켓 모두 20:00 마감). PC는 **BIOS 예약 켜기**로 그 전에 켠다(예: 20:20). Windows 작업 스케줄러는 "사용자의 로그온 여부에 관계없이 실행"으로 등록해서 로그인 없이 돈다. 실행이 빠진 날은 다음 실행 때 이어서 받는다. |
| 12 | 과거 상폐 종목 | **보류.** REST는 상폐 종목 가격을 주지 않는다. 매일 종목리스트를 저장해서 **앞으로** 상폐되는 종목은 자동으로 남긴다(`stocks.delisted`). 과거 상폐 종목이 빠져 있으므로 **백테스트 결과에 생존 편향이 있다**는 점을 감안한다. 기존 Open API의 상폐 26종목도 가져오지 않는다. |
| – | PC 역할 | 당분간 **데스크탑에서 개발과 수집·운영을 모두** 한다. 노트북은 쓰지 않는다. 코드는 GitHub 비공개 저장소(`woong2399/storage`)에 백업한다. |
| – | 언어 | Python 64비트 (DuckDB는 32비트를 지원하지 않는다) |

## 4. 전체 구조

```
[키움 REST] ───────────┐
[기존 Open API 데이터] ─┤→ ① 수집기 (속도 제한 · 재시도 · 이어받기 · IP 확인)
                        │
                        ↓
             ② 검증기 (이상값 · 누락일 · 수정주가 변경 감지) ──→ 📱 텔레그램
                        ↓
             ③ 저장소  storage.duckdb
                        ↓
             ④ 데이터 접근 계층  get_prices(종목, 기간, 수정여부, 시장)
                        ↓
             ⑤ (나중) 지표 계산기 → 지표 테이블
                        ↓
             ⑥ (나중) 시뮬레이터
```

각 부분은 따로 테스트할 수 있도록 파일 단위로 나눈다. 시뮬레이터는 ④만 보고, 수집 방식은 모른다.

## 5. 테이블 초안

| 테이블 | 한 줄 = | 주요 컬럼 |
|---|---|---|
| `stocks` | 종목 하나 | code, name, market(KOSPI/KOSDAQ), kind(보통주/우선주), foreign, first_seen, last_seen, delisted |
| `daily_bar` | 종목 × 날짜 × 시장 × 수정여부 | code, date, venue(KRX/KRX_REG/AL), adjusted(0/1), open, high, low, close, volume, amount(거래대금), source(rest/openapi), fetched_at |
| `minute_bar` | 종목 × 분 × 시장 | code, ts, venue, open, high, low, close, volume, source |
| `collect_state` | 작업 × 종목 | job, code, status, last_date, attempts, last_error, updated_at |
| `run_log` | 실행 한 번 | run_id, started_at, ended_at, status, summary |
| `adj_event` | 수정주가 변경 감지 한 건 | code, detected_at, reason, refetched, indicators_recalculated |
| `indicator_*` | (나중) 종목 × 날짜 | 지표값들 |

## 7. 미결정

없음. 0단계로 정해진 것: 우선주는 **종목코드 끝자리가 0이 아닌 것**으로 판별한다(`kind` 필드는 모두 `A`라서 쓸 수 없다). 스팩은 코스닥은 `companyClassName='스팩'`, 코스피는 이름의 「스팩」으로 거른다.

## 8. 0단계 테스트 항목

1. IP 제한이 실제로 걸리는지, 등록하지 않은 IP에서 어떤 오류가 오는지
2. 지속 가능한 호출 속도(10~30분 연속 호출), 시간당 누적 제한이 있는지, TR별로 제한이 따로 걸리는지
3. 같은 앱키로 노트북과 데스크탑에서 토큰을 발급받으면 앞서 발급한 토큰이 무효가 되는지
4. `ka10081` 수정주가: `upd_stkpc_tp=1` + 최근 `base_dt`로 연속조회 시 분할 이전 가격이 수정되는지 (삼성전자 2018-05)
5. 일봉을 과거 몇 년까지 주는지 (기존 데이터는 1985년부터)
6. `_AL`, `_NX` 접미사 일봉과 분봉의 종가·거래량 의미
7. `ka10080` 분봉을 2025년 10월까지 거슬러 받을 수 있는지
8. 종목리스트(`ka10099`) 응답에서 보통주·우선주와 ETF·스팩 등을 구분할 방법
9. 상폐 종목 코드로 `ka10081` 일봉을 요청하면 과거 가격을 주는지

#### KRX 종가 (가장 중요)

- **한국거래소가 2026-09-14부터 애프터마켓(16:00~20:00, 접속매매)을 개장**했다. 시간외 단일가는 폐지됐다.
- **2026-09-11까지:** 키움 KRX 일봉 종가 = KRX 분봉 15:30 봉 = 정규장 종가. 2025-10 ~ 2026-09 매달 하루와 08-19 ~ 09-11 매일을 확인했다.
- **2026-09-14부터:** KRX 분봉이 15:35 ~ 19:59까지 이어지고, **키움 KRX 일봉 종가 = 19:59 마지막 체결가**다. 정규장 종가는 15:30 분봉에만 있다.
  - 예: 삼성전자 2026-10-30 일봉 220,500 / 15:30 봉 225,000 / `_NX`·`_AL` 220,000
  - NXT 거래가 안 되는 종목(동화약품)도 똑같이 바뀌었다. NXT가 아니라 KRX 애프터마켓 때문이다.
- 그 전에도 `_NX`·`_AL`은 KRX와 다르다(예: 2025-10-15 삼성전자 KRX 95,000 / NX·AL 95,500).
- 기존 Open API `daily`는 **수집한 시각의 값**이라 2026-09-14 이후 날짜는 정규장 종가와 맞기도 하고 다르기도 하다. Open API `daily_regular`(분봉 09:00~15:30)는 15:30 종가와 일치한다.
- ✅ 영웅문(KRX 선택)의 2026-10-30 삼성전자 종가는 **220,500**이다. 키움 화면의 KRX 종가 = REST KRX 일봉 종가 = 애프터마켓 마지막 가격.
- ✅ **2026-09-14 이후 키움 KRX 일봉은 고가·저가·종가·거래량·거래대금이 모두 애프터마켓을 포함한다.** 시가는 09:00 봉과 같다. (`probe/p5_ohlcv.py`, 삼성전자·SK하이닉스·동화약품 × 09-11/09-14/10-15/10-30)
  - 예: 삼성전자 09-14 일봉 저가 247,000 = 분봉 전체 저가. 정규장 분봉 저가는 248,500.
  - 그래서 `KRX_REG`는 시가·고가·저가·종가·거래량을 **분봉 09:00~15:30으로 다시 만든다.**
  - 정규장 분봉 거래량 합은 일봉보다 조금 작다(09-11 기준 삼성전자 -11,566주, 약 0.08%). 분봉에 없는 장 마감 후 시간외 종가 체결로 추정한다. 분봉에 거래대금이 없어서 `KRX_REG`의 거래대금은 비워 둔다.

### 첫 전체 백필 결과 (2026-10-30 ~ 11-01)

- **수집:** 2,673종목, 일봉 1985~ (KRX·AL × 원·수정), 분봉 2025-10 ~ 2026-10. 남은 실패 0. DB 약 20GB (C 드라이브 여유 약 23GB).
- **키움 서버 일시 오류:** 분봉 백필 실패 535건 중 514건이 `return_code` 7 "서비스를 처리하는 중에 오류"[1631·1632], 6 "내부 호출 오류", HTTP 502였다. 07:53·10시대에 몰렸고 나머지는 시간당 20~30건 퍼져 있었다. → 5·15·30·60초 쉬고 재시도한다(`kiwoom.py`). 재실행으로 전부 받았다.
- **깨진 응답:** 약 12건은 숫자 칸에 다른 종목명("KODEX 레버리지")이나 제어문자가 섞여 왔다. 파싱 오류로 저장되지 않고 실패 처리됐고, 다시 받으면 정상이다.
- **⚠️ 끊긴 응답:** 서버가 불안정할 때 오류 대신 '정상' 응답으로 연속조회를 중간에 끊을 때가 있다. 32개 종목-월이 월초 며칠이 빠진 채 done 이 됐다(예: SK하이닉스 2026-07-01~07 + 07-08 오전). → 분봉을 저장하기 전에 일봉과 대조한다: 거래한 날의 분봉이 없거나, 그 전에도 거래한 종목인데 시작일 이전 봉에 닿지 않고 끝났으면(첫 거래일 09:00부터 있으면 예외) 저장하지 않고 실패로 남긴다(`minute.check_complete`). 사후 검사 후 73개 종목-월을 다시 받아, 거래한 날 분봉이 통째로 없는 경우 0.
- **⚠️ 키움 분봉 보관 기간은 약 1년:** 2026-11-01 현재 2025-11-03 이전 분봉을 주지 않는다. 2025-10 분봉은 10/31에 받아 둔 것이 유일하다 → **DB 백업이 필요하다.**
- **분봉 거래량 ≠ 일봉 거래량:** 2026-09-11 이전 날짜의 약 57%에서 분봉 합이 일봉보다 작다(삼성전자 2025-10-31: 3,669만 vs 5,482만). 일봉에는 시간외·대량(블록)매매가 들어가고 분봉에는 없다. Open API 분봉과 봉 집합·거래량이 같으므로 REST 문제는 아니다. 가격(OHLC)은 99.2% 일치.
  - 그래서 `KRX_REG` 거래량은 2026-09-11까지(일봉 복사)는 시간외·블록 포함, 2026-09-14부터(분봉 합)는 미포함이다. **시뮬레이터에서 거래량을 쓸 때 이 경계를 알고 써야 한다.**
