## 1. 백업과 자동 운영

**결정**
- DB는 D 드라이브로 옮기지 않는다. `data\storage.duckdb`(C 드라이브)에 그대로 둔다.
- 백업은 **한 달에 한 번**, 그달 **마지막 평일**에 수집이 끝난 뒤 G 드라이브(`G:\storage_backup`)로 복사한다.
  - 마지막 평일이 휴장이어도 DB에는 직전 영업일까지 들어 있으므로 그대로 백업한다.
  - 임시 이름으로 복사한 뒤 이름을 바꾼다. 도중에 끊겨도 이전 백업이 남는다.
- 백업이 실패해도 텔레그램으로 알린 뒤 PC는 끈다. 반대로 update가 실패하면 PC를 켜 둔다.

**작업 스케줄러**
- `storage_update`: 월~금 20:30
- `storage_weekend_off`: 토·일 20:40에 PC 종료. BIOS가 요일을 지정하지 못해 주말에도 20:20에 켜지기 때문이다.
- 비밀번호 방식 등록이 계속 실패했다. PC가 자동 로그인되는 환경이라 "로그온한 경우에만 실행" 방식으로 등록했다.
- BIOS 자동 켜짐: 매일 20:20 (사용자가 설정)
- 확인: 일요일 20:20 켜짐, 20:40 주말 종료 작업, 20:42 종료가 모두 정상 동작했다.

**매일 흐름** (`scripts\run_update.bat` → `after_update.ps1`)
1. update
2. 월말이면 백업
3. 텔레그램 "수집 끝, 2분 뒤 종료" 알림
4. `shutdown /s /t 120` (취소: `shutdown /a`)

**텔레그램 알림**
- 보내는 것: 시작, 25·50·75% 진행, 완료 요약, 백업 완료·실패, 종료 예고, IP 변경, DB 잠김
- `python -m storage notify "글"`: DB를 열지 않고 알림만 보낸다. 배치·PowerShell 단계에서 쓴다.
- `/status` 봇은 상시 실행하지 않기로 했다. 진행 상황은 알림으로 받는다.

**그 밖에**
- `storage_openapi` 폴더(옛 Open API 수집기와 대조용 분봉 1.2GB)를 휴지통으로 보냈다.
- `feat/collector`를 main에 합치고 GitHub에 푸시했다.

## 2. 키움 일봉 오류 보정 (2001-03-23·07-03 등 47건)

**문제**
- 문서에 있던 "2000년 전후 10배 차이"를 조사해 보니 원인이 두 가지였다.

**원인 1: 9종목의 9거래일 차이**
- 해당 종목: 000040·001260·003060·004870·012170·025620·030350·032860·060900
- 감자·병합 반영일을 REST와 Open API가 9거래일 다르게 잡았다.
- 어느 쪽이 맞는지는 확인하지 못했다. 문서에만 기록했다.

**원인 2: 키움 환산 누락 47건**
- 키움은 나중의 액면분할·병합에 맞춰 과거 일봉을 환산하는데, 2001-03-23(31종목)과 2001-07-03(10종목) 등 특정 날짜를 빠뜨렸다.
- 그래서 그날만 원본 단위로 남아 10·5·2·0.5배로 튀었다.
- 확인 방법:
  - Yahoo Finance 시세와 대조했다.
  - KRX 정보데이터시스템 원본과도 대조했다. 사용자가 브라우저로 직접 로그인한 뒤 수동으로 조회했다.
  - 2001년 41건은 확인했고, 1985~96년 6건은 KRX에 원본이 없어 미확인이다.
- 보정 방법:
  - 가격은 ÷k, 거래량은 ×k로 고친다.
  - `daily.KNOWN_UNCONVERTED`에 목록을 두고, 키움에서 받을 때마다 적용한다. 그래야 수정주가를 다시 받아도 되살아나지 않는다.
  - 기존 DB는 한 번 보정했다.
- 커밋: `6dc1a3d`

## 3. 새 데이터와 대시보드 (커밋 `cb1f947`)

**지금 DB에 있는 것**
- `daily_bar`(일봉), `minute_bar`(1분봉), `stocks`(종목)
- 지표는 계산해 두지 않았다. 의도적인 결정이다.

**새로 추가한 것**
- **`kiwoom_mktcap`**
  - ka10099 상장주식수 × **정규장 종가**(KRX_REG, KRX 공식 시가총액과 같은 기준)
  - 매일 update에서 쌓는다. 추가 호출은 없다.
  - 키움 ka10001도 시가총액을 주지만, 억 원 단위이고 종목마다 호출해야 해서(15분 증가) 쓰지 않는다.
- **`krx_daily`**
  - KRX 시가총액·거래대금·상장주식수를 담는다. 키움 값과 섞지 않으려 컬럼 이름에 `krx_`를 붙였다.
  - 아직 비어 있다.
- **`minute_bar_amount` 뷰**
  - est_amount = (시가+고가+저가+종가)/4 × 거래량. 키움 분봉 API에는 거래대금이 없다.
- **대시보드**
  - 실행: `python -m storage dashboard [--lan]` → http://127.0.0.1:8765
  - 요청마다 DB를 읽기 전용으로 열고 닫는다.
  - 수집 중에는 조회되지 않는다.

**거래대금 품질**
- 키움 일봉의 옛 거래대금은 단위가 맞지 않는다. 예: 삼성전자 1990년 값이 19백만 원.
- 거래량은 있는데 거래대금이 0인 행이 51만 개 있다.

**보류**
- 읽기 전용 DB 복사본: 수집 후 메인 DB를 복사해 두고 조회는 복사본으로 하는 방식. 첫 실전 수집을 확인한 뒤에 정한다.
- staging 방식도 논의만 했다.

## 4. KRX 과거 시가총액 수집 시도와 차단

**시도한 것**
- data.krx.co.kr 전종목 시세를 날짜별로 자동 조회했다. 앱 브라우저가 다운로드를 막아서 크롬(Claude in Chrome)으로 실행했다.

**결과**
- 약 1,000건 조회한 뒤 **IP가 1일 차단**됐다.
- 차단 안내: 자동화 수단으로 대량 조회하는 것은 이용약관 제10조 제2호 위반이고, 다시 탐지되면 재차단한다.

**결정**
- data.krx.co.kr 자동 수집은 다시 하지 않는다.
- **KRX Open API**(openapi.krx.co.kr)를 공식 경로로 쓴다.
  - 사용자가 가입하고 인증키를 신청한다. 신청할 서비스: 유가증권·코스닥 일별매매정보
  - 받은 키는 `.env`의 `KRX_API_KEY`에 넣는다.
- 참고:
  - KRX 데이터는 1995-05-02부터 있다.
  - KRX 종가와 시가총액은 정규장 종가 기준이다. 예: 삼성전자 10-30은 225,000원이고, 키움 KRX 일봉은 애프터마켓 종가 220,500원이다.

## 8. 클라우드: MotherDuck (11-02, 커밋 `0b4d3d3`, `7fcf081`)

**왜**
- 핸드폰·채팅에서도 조회해 보려고. PC는 평일 저녁 수집 때만 켜져 있다.
- 분봉을 빼면 일봉은 Parquet 으로 약 210MB 라 무료 클라우드에 충분히 올라간다.

**결정**
- **MotherDuck**(클라우드 DuckDB, 무료 Lite 플랜, 카드 없이)에 데이터를 둔다.
- MotherDuck 의 기존 `stocks` DB(예전 매매일지·종목 메모)는 손대지 않는다. 지울지는 사용자가 직접 판단한다. 새 데이터는 별도 `storage` DB 에 올린다.
- 토큰: PC 용 `woong_stock_pc`(읽기·쓰기, `.env` 의 `MOTHERDUCK_TOKEN`), 조회용은 따로 만든다(읽기 전용 권장).

**구현**
- MotherDuck 이 DuckDB 2.0 을 아직 지원하지 않는다(최신 지원 1.5.6). 그래서 두 단계로 나눴다.
  1. `python -m storage cloud-export [--full]`: `data\cloud\` 에 Parquet 을 만든다 (DuckDB 2.0).
  2. `.venv-md\Scripts\python scripts\cloud_upload.py`: MotherDuck 에 올린다 (업로드 전용 환경, DuckDB 1.5.6).
- 올리는 것: `daily`(정규장 수정주가 OHLCV + 정규장 원주가 종가 `raw_close` + KRX 거래대금 `amount`), `stocks`, `kiwoom_mktcap`, `krx_daily`.
- 처음 전체 1,237만 행은 30초, 이후에는 최근 10일 + 수정주가가 바뀐 종목만 올라가 수 초면 된다.
- 매일 수집 뒤 `after_update.ps1` 이 자동으로 올리고 텔레그램(☁️)으로 알린다. 실패해도 PC 는 끈다.

**Claude 일반 채팅**
- 사용자 계정에 MotherDuck 커넥터가 이미 연결돼 있다. Claude 앱 채팅에서 **PC 가 꺼져 있어도** MotherDuck 을 조회할 수 있다.
- 이 Claude Code 세션은 PC 에서 돌아서 PC 가 꺼지면 응답할 수 없다.
- 채팅용 인수인계 문서: `docs/handoff-chat.md` (커밋 `e07f592`).

- **키움 시가총액 첫 행:** 상장주식수 2,673종목, 시가총액 2,562종목(합계 약 5,230조 원). 예: 삼성전자 229,000원 × 58.5억 주 = 1,339조 원.
