# woong_stock 데이터 수집 정리

키움 **REST API**로 국내 주식 일봉·분봉을 모아 DuckDB 한 파일에 쌓는다. 데이터 원천이다.
결정의 이유와 0단계 시험 결과는 [design.md](design.md)에 있다. 이 문서는 "지금 무엇이 어떻게 쌓여 있고, 쓸 때 무엇을 조심해야 하는지"를 정리한다.

> 기준: 2026-11-01 첫 전체 백필과 검증을 마친 시점

## 1. 한눈에 보기

| 항목 | 현재 |
|---|---|
| 종목 | 2,673개 (코스피 보통주 803·우선주 111, 코스닥 보통주 1,756·우선주 3, 그중 외국기업 15) |
| 일봉 | 1985-01-04 ~ 2026-10-30, 시장 3종(KRX·KRX_REG·AL) × 원주가·수정주가 |
| 분봉 | 2025-10-01 ~ 2026-10-30, 1분봉, KRX 원주가, 1억 6,927만 봉 (2,636종목) |
| 남은 수집 실패 | 0 (collect_state 40,095건 모두 done) |
| DB | `data/woong_stock.duckdb`, 약 20GB |
| 매일 갱신 | 평일 20:30 `update` (작업 스케줄러 `woong_stock_update`), 끝나면 PC 종료 |
| 알림·조회 | 텔레그램 봇 @woong99_alert_bot, `/status` |

## 2. 무엇을 모으나

- **종목:** 코스피·코스닥의 **보통주와 우선주만** 모은다. ETF·ETN·스팩·리츠·인프라/선박펀드·코넥스는 뺀다. 외국기업은 포함하고 `foreign = true`로 표시한다.
  - 우선주 판별: 종목코드 마지막 글자가 `0`이 아니면 우선주다.
- **상장폐지 종목:** 과거에 상장폐지된 종목은 아직 없다. 키움이 빈 행만 주기 때문이다. → 백테스트에 **생존 편향**이 있다. 수집을 시작한 뒤 상장폐지되는 종목은 `delisted = true`로 남기고 데이터는 지우지 않는다.
- **일봉 시리즈:**

  | venue | 뜻 | 기간 | 원주가 / 수정주가 |
  |---|---|---|---|
  | `KRX` | 키움 KRX 일봉 그대로 (영웅문 KRX 화면과 같음) | 1985~ | 둘 다 |
  | `KRX_REG` | **정규장(09:00~15:30) 일봉** — 정규장 기본값 | 1985~ | 둘 다 |
  | `AL` | 통합 시세 (KRX+NXT, `종목코드_AL`) | 2025-03-04(NXT 출범)~ | 둘 다 |

- **분봉:** 1분봉, KRX, **원주가만**. 2025-10부터.
- **지표:** 수집기는 계산하지 않는다. 나중에 따로 계산해 별도 테이블에 넣는다.

### KRX_REG가 따로 있는 이유 (중요)

한국거래소가 **2026-09-14부터 애프터마켓(16:00~20:00)**을 열었다. 그날부터 키움 KRX 일봉은 고가·저가·종가·거래량·거래대금에 **애프터마켓 체결이 섞인다.** 종가는 19:59의 마지막 체결가가 된다.
예: 삼성전자 2026-10-30 KRX 일봉 종가 220,500 / 정규장 종가(15:30 분봉) 225,000.

그래서 정규장만 보는 `KRX_REG`를 이렇게 만든다.
- **2026-09-11까지:** KRX 일봉을 그대로 복사한다. 이때는 KRX 일봉 = 정규장이었다.
- **2026-09-14부터:** 분봉 09:00~15:30으로 다시 만든다. 수정주가는 같은 날 KRX의 (수정 종가 ÷ 원 종가) 비율로 계산한다. 분봉에는 거래대금이 없어 `amount`는 비운다.

## 3. 테이블

| 테이블 | 키 | 내용 |
|---|---|---|
| `stocks` | code | 이름, 시장(KOSPI/KOSDAQ), 보통주/우선주, foreign, nxt(NXT 거래 가능), first_seen, last_seen, delisted |
| `daily_bar` | code, date, venue, adjusted | open, high, low, close, volume, amount(백만원), source, fetched_at |
| `minute_bar` | code, ts, venue | open, high, low, close, volume, source |
| `minute_bar_amount` (뷰) | — | minute_bar + est_amount = (시가+고가+저가+종가)/4 × 거래량. 키움 분봉에 거래대금이 없어 조회할 때 계산한다 |
| `kiwoom_mktcap` | code, date | 키움 기준 시가총액(원). 상장주식수(ka10099 listCount) × 정규장 종가(KRX_REG 원주가, KRX 공식 시가총액과 같은 기준). 매일 update에서 쌓으며 2026-11-02부터 있다 |
| `krx_daily` | code, date | KRX 전종목 시세: krx_close, krx_volume, krx_amount(원), krx_mktcap(원), krx_list_shrs. 키움 값과 섞지 않으려 따로 둔다. **비어 있음** — KRX Open API 키를 받으면 채운다 (data.krx.co.kr 자동 조회는 약관 위반으로 IP 차단됨) |
| `collect_state` | job, code | 작업별 종목 상태(done/failed), 시도 횟수, 마지막 오류. 이어받기에 쓴다 |
| `run_log` | run_id | 명령별 실행 기록(시작·끝·상태·요약) |
| `adj_event` | — | 수정주가가 바뀐 것을 감지한 기록(분할·증자 등). 지표를 다시 계산할 때 쓴다 |

조회할 때는 이렇게 쓴다.

```python
from woong_stock import db
con = db.connect()
rel = db.get_prices(con, date(2020, 1, 1), date(2026, 10, 30))       # 기본: KRX_REG, 수정주가
df = rel.df()
```

## 4. 수집 방식

- **API:** `ka10099` 종목 목록, `ka10081` 일봉(페이지당 약 600일), `ka10080` 분봉(페이지당 900봉). 연속조회는 `cont-yn`/`next-key` 헤더로 한다.
- **속도:** 초당 3회(0.34초 간격). 시험에서는 초당 5회로 18분을 호출해도 429(호출 제한)가 나지 않았다.
- **재시도:**
  - 429: 2·4·8·16·32초 쉬고 다시 한다.
  - 네트워크 오류: 5초 간격으로 3번 다시 한다.
  - **서버 일시 오류**(HTTP 5xx, `return_code` 6·7 "서비스를 처리하는 중에 오류"): 5·15·30·60초 쉬고 다시 한다.
  - 토큰 만료(401, "8005"): 토큰을 새로 받아 한 번 다시 한다.
- **끊긴 응답 검사:** 분봉을 저장하기 전에 일봉과 대조한다. 서버가 불안정할 때 오류 대신 '정상' 응답으로 연속조회를 중간에 끊는 일이 있었다.
  - 일봉에 거래가 있는 날인데 분봉이 없으면 실패로 처리한다.
  - 전에도 거래한 종목인데 시작일 이전 봉에 닿지 않고 끝났으면 실패로 처리한다. 단, 첫 거래일 09:00부터 있으면 인정한다(분봉 보관 기간 경계).
  - 실패하면 저장하지 않는다. 기존 데이터는 그대로 남는다.
- **이어받기:** 종목마다 `collect_state`에 결과를 남긴다. 같은 명령을 다시 실행하면 끝난 종목은 건너뛰고 실패한 종목만 다시 받는다.
- **IP:** 키움 포털에 등록된 IP에서만 호출된다. 매일 실행할 때 공인 IP가 바뀌었으면 알린다. 실제로 막히면(IpNotAllowed) 멈추고 "새 IP 등록 필요"를 알린다.

## 5. 실행 방법

PowerShell에서 `C:\Users\Jinwo\woong_stock` 기준으로 실행한다.

| 명령 | 하는 일 |
|---|---|
| `.venv\Scripts\python -m woong_stock stocks` | 종목 목록 갱신 |
| `.venv\Scripts\python -m woong_stock backfill-daily` | 전 종목 일봉 백필 (이어받기) |
| `.venv\Scripts\python -m woong_stock backfill-minute [--months 202510 ...]` | 분봉 백필. 기본은 2025-10부터 이번 달까지 (오늘이 1일이면 이번 달은 뺀다) |
| `.venv\Scripts\python -m woong_stock update` | 매일 작업 (아래) |
| `.venv\Scripts\python -m woong_stock check [--days 7]` | 최근 일봉 검증 |
| `.venv\Scripts\python -m woong_stock crosscheck` | 기존 Open API 데이터와 대조 (읽기 전용) |
| `.venv\Scripts\python -m woong_stock bot` | 텔레그램 조회 봇. 계속 켜 둔다 |
| `.venv\Scripts\python -m woong_stock dashboard [--lan]` | 표로 보는 대시보드 (http://127.0.0.1:8765). 수집 중에는 조회 안 됨 |
| `scripts\backfill_all.bat` | 처음 한 번: stocks → 2025-10 분봉 → 대조 → 일봉 → 나머지 분봉 → 대조 |
| `scripts\run_update.bat` | 작업 스케줄러가 부를 매일 실행 |

DB는 한 번에 한 프로그램만 쓸 수 있다. 백필 중에 `update` 등을 실행하면 "DB 잠김" 알림을 보내고 끝난다. 봇은 DB를 열지 않으므로 백필 중에도 동작한다.

## 6. 매일 작업 (`update`, 평일 20:30)

1. 공인 IP를 확인하고, 바뀌었으면 알린다.
2. 휴장일 확인: 삼성전자 일봉에 오늘 날짜가 없으면 "휴장"을 알리고 끝낸다.
3. 종목 목록 갱신: 신규 상장은 추가하고, 상장폐지는 표시한다. 그날의 상장주식수도 `kiwoom_mktcap`에 남기고, 일봉을 받은 뒤 종가를 곱해 시가총액을 채운다.
4. 종목마다 일봉 4종(KRX·AL × 원·수정)을 최근 1페이지씩 받고, 분봉은 마지막으로 저장된 날부터 오늘까지 받는다.
   - 그 기간 일봉 거래량이 모두 0이면(거래정지) 분봉을 조회하지 않는다. 분봉이 없거나 마지막 분봉이 키움 보관 기간(약 1년, `MINUTE_RETENTION_DAYS`=360일)보다 오래됐으면 보관 기간 안에서 시작한다. (11/02 첫 자동 수집에서 거래정지 37종목·보관 기간 밖 1종목이 매일 실패로 잡힌 문제)
   - 수정 종가가 과거와 달라졌으면(권리 이벤트) 수정주가 전체를 다시 받고 `adj_event`에 남긴다.
5. 최근 7일의 KRX_REG를 다시 만든다. 수정주가가 바뀐 종목은 KRX_REG 전체를 다시 만든다.
6. 검증(고가<저가, 0 이하 가격, 범위 밖 종가, 빠진 날)을 하고 결과를 텔레그램으로 보낸다.

## 7. 클라우드 (MotherDuck)

- 분봉을 뺀 데이터를 MotherDuck 의 `woong_stock` 데이터베이스에 올린다. 테이블: `daily`(정규장 수정주가 OHLCV + 정규장 원주가 종가 `raw_close` + KRX 일봉 거래대금 `amount` 백만 원), `stocks`, `kiwoom_mktcap`, `krx_daily`.
- MotherDuck 이 DuckDB 2.0 을 아직 지원하지 않아 두 단계다: `python -m woong_stock cloud-export [--full]` 이 `data\cloud\` 에 Parquet 을 만들고, `.venv-md\Scripts\python scripts\cloud_upload.py`(DuckDB 1.5.6 전용 환경)가 올린다. 토큰은 `.env` 의 `MOTHERDUCK_TOKEN`.
- 매일 update 뒤 `after_update.ps1` 이 자동으로 올린다. 처음만 전체(약 1,240만 행, 30초), 이후는 최근 10일 + 수정주가가 바뀐 종목만(수 초). 실패해도 알림 후 PC 는 끈다. 다시 전체를 올리려면 `cloud-export --full`.
- `.venv-md` 는 Git 에 올리지 않는다. 새 PC 에서는 `python -m venv .venv-md` 후 `pip install duckdb==1.5.6`.

## 8. 알림과 조회

- **텔레그램 알림:** 백필·update의 시작과 완료, 백업 완료·실패, PC 종료 예고, 25·50·75% 진행, 실패, IP 변경과 차단, DB 잠김을 보낸다. 키는 `.env`의 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`에 있다.
- **`/status`:** 봇에게 보내면 최근 로그 두 파일을 읽어 답한다(DB는 열지 않는다). 진행률, 월별 완료, 종목 실패 원인, 최근 오류가 나온다. 본인 chat_id에만 답한다.
- **로그:** `logs\YYYY-MM-DD.log`. 100종목마다 진행 줄과 종목별 실패 원인이 남는다. 자정을 넘긴 실행은 시작한 날 파일에 계속 쓴다.

봉 집합(어느 분에 봉이 있는지)은 2025-10 분봉에서 양쪽이 완전히 같았다.

### 키움 일봉 환산 누락 47건 (보정함)

키움은 나중의 액면분할·병합에 맞춰 과거 일봉을 환산해 주는데, **2001-03-23(31종목)·2001-07-03(10종목)**과 1985~1996년 6건은 그날만 환산이 빠져 원본 단위로 남아 있었다. 그래서 그날만 10·5·2·0.5배로 튀었다가 다음 날 돌아온다(예: 노루홀딩스 3,185 → 32,200 → 3,400). Open API도 같은 값이라 대조에서는 걸리지 않았다.
- 2001년 41건은 KRX 정보데이터시스템 원본과 대조해 확인했다(2026-11-01). 1985~1996년 6건은 KRX에 그 시기 원본이 없어 미확인이다.
- 보정: 가격 ÷k, 거래량 ×k, 거래대금은 그대로. `daily.KNOWN_UNCONVERTED`에 목록이 있고, 키움에서 일봉을 받을 때마다 적용한다(수정주가 전체 재수집 때 되살아나지 않게). 기존 DB는 2026-11-01에 보정했다.
- 남은 이상치(보정 안 함): 대한방직 1987-07-21, 한국알콜 1996-09-18, HLB 2002-04-01, SM Life Design 2001-12-18. 거래가 거의 없던 날의 값으로 보이며 확인하지 않았다.

## 10. 데이터를 쓸 때 조심할 것

1. **기본은 `KRX_REG` + 수정주가.** `KRX`는 2026-09-14부터 애프터마켓이 섞여 정규장 전략에 맞지 않는다.
2. **KRX_REG 거래량의 경계:** 2026-09-11까지는 시간외·대량(블록)매매가 **포함**되고(일봉 복사), 2026-09-14부터는 **빠져** 있다(분봉 합). 거래량 기반 신호는 이 날짜에서 수준이 달라질 수 있다. 참고로 2026-09-11 이전에 분봉 거래량 합이 일봉보다 작은 날이 약 57%다. 예: 삼성전자 2025-10-31 3,669만 vs 5,482만.
3. **KRX_REG 거래대금은 2026-09-14부터 비어 있다.**
4. **분봉은 원주가다.** 분할·병합이 있는 종목은 일봉의 수정 비율로 맞춰 써야 한다.
5. **생존 편향:** 과거 상장폐지 종목이 없다.
6. **9종목의 9거래일 10배 차이**(9장)는 출처끼리 다르다. 그 종목·구간(1997~2004)을 쓰는 전략이면 확인이 필요하다.
7. **분봉 시각:** `ts`는 키움 체결 시각 기준이다. 15:30 봉은 장 마감 동시호가이고, 2026-09-14부터는 15:35~19:59 봉(애프터마켓)도 있다.

## 11. 운영 리스크

- ⚠️ **키움 분봉은 약 1년만 보관한다.** 2026-11-01 현재 2025-11-03 이전 분봉은 주지 않는다. 지난 분봉은 우리 DB가 유일한 사본이므로 **백업이 필수다.**
- **백업:** DB는 `data\woong_stock.duckdb`(C 드라이브)에 그대로 두고, G 드라이브(`G:\woong_stock_backup`)에 한 벌 복사한다. `scriptsackup.bat`이 임시 이름으로 복사한 뒤 바꿔치므로 도중에 끊겨도 이전 백업이 남는다. `run_update.bat`이 **그달의 마지막 평일**에만 update 직후 자동으로 부른다(그날이 휴장이어도 직전 영업일까지 다 들어 있다). 그 밖에는 `scriptsackup.bat`을 직접 실행한다. 복사 중 일시적으로 DB 크기의 2배(약 45GB)가 G에 필요하다.
- **디스크:** DB 20GB, 분봉이 매달 약 1.3GB씩 는다. C 드라이브 여유는 현재 약 100GB, G는 약 103GB다.
- **키움 서버 불안정:** 주말과 오전에 일시 오류가 몰릴 수 있다. 재시도와 끊긴 응답 검사로 막고, 그래도 실패하면 기록이 남으니 다시 실행하면 된다.
- **봇:** `/status` 조회용. 쓰지 않을 예정이라 자동 실행하지 않는다. 진행 상황은 알림으로 받는다.
