# 2026-11-06 Assistant — 종목 창고와 자동화 (상세)

## 대화의 주요 흐름
1. **Surge 10%↑ 를 구글 시트로.** 새 스프레드시트 `surge`, 11/02~11/05 전체 156건. 처음엔 월별 탭(`2026-11`)으로 만들었다가 나중에 `이력` 한 탭으로 바꿈(사용자 선택). 열은 date, code, name, pct, amount_est.
   - 종목 코드 앞자리 0(예 `004545`)이 사라지지 않게 A·B열을 **텍스트 서식**으로 지정한 뒤 값을 씀.
2. **텔레그램 글을 옆 열에.** `daily_data\data\날짜.json` 의 `issue` 를 이력에 넣음(173행 중 111행에 글이 있음). 텔레그램에만 있는 17종목도 넣으라는 요청 → 각 날짜 블록 맨 아래에 행을 끼워 넣음(11/02 9, 11/03 4, 11/05 4). 거래대금은 비움.
3. **등락률·코드를 "우리 DB"로.** 로컬 DuckDB 는 Storage 수집(`storage flow`, PID 7992 등)이 계속 잡고 있어 열 수 없었다. MotherDuck `storage.daily` 에서 전일 종가 대비로 계산한 값을 사용. 거래대금은 MotherDuck `amount`(애프터마켓 포함)라 기준이 달라서 쓰지 않고, **정규장 `amount_est` 는 수집 후 로컬 DB 로** 채우기로 함.
   - 영광(`359410`) 11/02: 신규상장 첫날이라 전일 종가가 없어 DB 등락률이 null. 21,500 ÷ 1.2647 ≈ 17,000 → 공모가 기준 26.47%로 보이나 미확인. 텔레그램 값 유지.
   - 씨케이솔루션(`480370`) 11/02: 텔레그램 10.16%, DB 9.17% → DB 값 사용, 원인 미확인.
4. **코드로 만들기.** `surge\surge_sheet.py` (월별 CSV 생성), `run_surge_sheet.bat`. 이후 열 배치 변경에 맞춰 수정.
5. **종목 창고 설계 요구:** 종목별·날짜별 이슈, 종목에 들어가면 테마와 종목 정보 입력 공간, 관련 이슈, 테마별 검색. 결정: 기록은 `이력` 한 탭, 테마는 텔레그램에서 자동 추출 후 직접 수정 → 곧 "내가 직접 입력"으로 바뀌었다가 다시 "텔레그램 참고해서 채워줘"로 바뀜.
6. **시트 구조 만들기(Sheets 커넥터).**
   - `이력`: A~E 기존, **F theme(직접 입력, 노란 칸), G telegram, H news**(사용자가 헤드라인·링크를 겁니다).
   - `종목`: A 코드(155개, 텍스트), B 이름·C 테마·F 횟수·G 최근일·H 선택용은 ARRAYFORMULA/BYROW 수식, D 종목 정보·E 메모는 직접 입력.
   - `종목보기`(드롭다운으로 종목 선택), `날짜별`(날짜 드롭다운), `테마별`(테마 드롭다운), `테마`(이력 F열에서 자동 모은 테마 목록).
   - 시행착오: BYROW 수식의 괄호 하나가 많아 `#ERROR!` → 고침. 시트 그리드 밖(J열)에 시험 수식을 쓰려다 오류 → 빈 `테마` 탭에서 시험.
7. **사고 1 — 텔레그램 열이 지워짐.** 사용자가 F열(그때는 텔레그램 열)에 `thema` 머리글로 테마를 직접 입력하면서 텔레그램 내용이 덮어써졌다. 사용자 요청으로 "바꾸기 전으로" 되돌림: 텔레그램을 F열에 복구하고 제가 만든 열을 지움(사용자가 입력한 theme 값 일부는 `scratchpad\user_thema_backup.txt` 에 옮겨 적었으나 행 번호가 어긋났을 수 있음 — 불완전 백업). 이후 사용자가 "F열 왼쪽에 열을 추가해 테마, G는 뉴스"라고 해서 배치 결정: **F theme / G telegram / H news**.
8. **Claude 아티팩트 대시보드**(`Surge 종목 창고`)를 만들었으나, 사용자가 Streamlit 으로 만들겠다고 해서 사용하지 않음. 데이터는 복사본(history.json 173행).
9. **Streamlit 앱 `surge_app`.** 사용자 요구: 1장 날짜별 종목 이슈, 2장 종목별, 3장 테마별(종목별 급등 횟수 같은 건 필요 없음). 결정: 새 폴더 `surge_app`, 처음엔 MotherDuck 에 올려 읽기였으나 사용자가 "이력 시트를 수정하면 Streamlit 도 수정돼야 한다"고 해서 **시트를 CSV(gviz)로 직접 읽기**로 바꿈 → 시트를 "링크가 있는 누구나 보기"로 공유(사용자 동의).
   - 시트 읽기: `https://docs.google.com/spreadsheets/d/<id>/gviz/tq?tqx=out:csv&sheet=<탭>`, `dtype=str` 로 읽어 코드 앞 0 보존. 캐시 60초.
   - GitHub 새 공개 저장소 `woong2399/surge_app`(사용자가 직접 만듦, 이 PC 에 `gh` 없음) → 내가 push. Streamlit 클라우드 배포는 사용자가 직접(주소 `surge-warehouse.streamlit.app`).
   - 폰 화면 수정 요청(사진): 제목 잘림 → 위쪽 여백 늘림, 메뉴 이름 `app` → **이슈·종목·테마**(`st.navigation` + `views/` 폴더로 구조 변경), 이슈에서 테마 글씨 키우기, 종목·테마에 옆 목록 → 이후 "**이슈처럼 목록을 맨 위에, 검색을 아래에**"로 다시 변경, 맨 위 메뉴 3개 제거 + 카드형 재디자인(Pretendard 글꼴, 등락률 알약, 다크 모드 색).
   - 시행착오: 글꼴을 `[class*="st-"]` 전체에 강제했더니 사이드바 아이콘 자리에 `keyboard_double_` 글자가 보임 → 아이콘(`stIconMaterial`)을 제외하도록 수정. 폰 크기로 열어 보고 발견.
   - 종목 화면에 **테마 변화** 추가: 날짜별 테마를 보여 주고 처음 나온 테마는 윤곽선.
10. **자동화.** 사용자: "다 코드로 자동화하자". 서비스 계정 방식 선택(앱은 읽기 전용, 스크립트는 서비스 계정으로 시트에 씀). `gspread` 를 Storage `.venv` 에 설치(이 파이썬이 DuckDB 2.0 형식을 읽음).
    - `surge_auto.py` 순서: (1) `surge_daily.py` — DB 잠김이면 10분 간격 6번 재시도, 휴장일·수집 전은 종료 코드 1 (2) `build_daily_json.py --since 날짜` (3) `surge_sheet.build_day` 로 행 만들기, 텔레그램에만 있는 종목은 DB 로 등락률·거래대금 채움 (4) 테마를 텔레그램 글에서 뽑기 (5) 시트 `이력` 에 없는 (날짜, 코드) 행만 아래에 붙이고, 있는 행은 빈 칸(거래대금·등락률·테마·텔레그램)만 채움, `종목` 탭에 새 코드 붙임. 값은 RAW 로 써서 코드 앞 0 유지.
    - 테마 규칙: 사용자가 "이미 테마가 있는 종목은 다른 테마가 오면 추가"를 요청 → 처음엔 새 행에 그 종목의 옛 테마를 복사하도록 짰다가, 사용자가 "날짜마다 테마가 들어가니 테마의 변화도 알 수 있겠네"라고 해서 **새 행에는 그날 테마만** 적고, 종목 전체 테마는 합쳐서 보여 주는 방식으로 고침.
    - 시험: 가짜 gspread 로 규칙 확인(기존 행 빈 칸만 채움, 새 날짜는 그날 테마만, 새 종목은 `종목` 탭에 추가), 서비스 계정으로 실제 시트 읽기와 `--dry-run` 통과. DB 가 잠겨 있으면 "수집이 끝난 뒤 다시 실행하세요"로 종료하는 것도 확인.
    - 키 파일: 사용자가 내려받은 JSON 이름이 `galvanic-style-…json` 이어서 `service_account.json` 으로 이름 변경. 내용은 출력하지 않았다.
