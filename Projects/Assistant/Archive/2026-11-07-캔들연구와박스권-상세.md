# 2026-11-07 Assistant — 캔들 연구와 박스권 (상세)

## A. 기준봉 + 480일선 돌파 연구 (세션 앞부분, 요약)
- 출발: 사용자가 예전에 말한 "기준봉"(거래대금 150억?)을 찾아 달라고 함 → 조건 캔들 정의 → "계속 하락하다가 기준봉이 나오고 추세가 바뀌는" 종목을 1년 이상 하락 조건으로 → 480일선 아래 큰 산 → 시세·돌파 시도 정의를 사용자가 여러 번 고침(20거래일 안에 480일선 아래로 되돌아오면 "시도", 시세 20%, 저점 대비 100% 이상 등). 기준 예시 종목으로 **금강철강**을 줌(23년 9월 데드크로스 후 하락, 24~25년 여러 번 거래대금 터지며 돌파 시도, 26년 4월 고점 돌파 후 100%↑ 시세).
- "거래대금이 전봉 대비 몇 %인지", "시총 대비 비율"을 봄. 한온시스템·부광약품·나노팀으로 시험. 사용자: "튐의 횟수는 상관없다", "가격 조건은 두지 마", "시세가 나오기 전을 봐야 한다".
- 그 뒤 "이전 기준은 고려하지 말고 **500억 기준봉으로 480일선을 돌파한 사례를 전 종목에서**" 로 바뀜 → 1,837건(탭 `500돌파`: 종목·날짜·거래대금/시총 비율).
- 20거래일 결과: "20거래일째 종가가 아니라 날짜 기준 종가 몇 %" → 그 기간의 최대 상승·최대 하락. 시총 대비 비율 중 50% 이상으로 추려 봄(전체 1,837 중 1,079건).
- 반값 매수 시나리오: "5거래일 안에 기준봉 1/2 지점 종가로 매수 후 20거래일" → 탭 `반값매수`(매수일+1~+20일 등락률 24열).
- 계산이 오래 걸려 질의를 `lead()` 열로 바꾸고 파이썬으로 처리(UNBOUNDED FOLLOWING 윈도우·같은 CTE 두 번 계산이 원인). MotherDuck 은 하루 한도에 걸려 **로컬 DB 를 우선** 쓰기로.
- 새 기준: "최근 기준봉 이전 240거래일 안에서 시세(저점 이후 최대 상승)가 50% 이하" → 500억 158건 / 150억 352건. 사용자가 "500억을 150억으로 줄여보자"고 해서 150억 결과를 계산한 뒤 "시트 내용 다 지워줘"가 와서 **캔들 시트 전체 탭의 값을 비움**.
- 앞서 사용자가 지적한 실수: 150억을 다시 끼워 넣음, "시총 6%" 와 중앙값 용어 혼선, 기준 말뜻을 추측해 여러 번 다시 만듦 → 그래서 "하기 전에 확인 먼저 받아"(메모리 저장).

## E. 시행착오
- `gspread` 서비스 계정에 새 시트 접근 권한이 없어서 직접 쓰기 실패 → 사용자가 시트를 서비스 계정에 편집자로 공유한 뒤 해결(`candle` 시트 때와 같은 방식).
- PowerShell `Stop-Process` 로 파이썬 프로세스를 죽이려던 시도는 자동 권한 검사에서 거부 → 내가 띄운 백그라운드 작업은 `TaskStop` 으로만 멈춘다.
- `\U` 가 들어간 독스트링이 유니코드 이스케이프 SyntaxError → 원시 문자열로.
