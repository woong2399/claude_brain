## 결정 (이유)
- **웹 수집으로 간다**(사용자). RSS 는 건수·범위 한계가 있고 날짜 지정이 안 돼서. 단점(사이트 개편 시 깨짐, 매체마다 코드)은 알려 드림.
- **한경 먼저, 확인 후 확장**(사용자).
- **11월 1일 기사만**(사용자, 일단). 사이트맵에는 그날 *수정된* 옛 기사도 섞여 있어서, 기사 주소의 날짜가 그날인 것만 받는다 (209건 → 179건).
- 사이트맵에는 제목이 없어서 **기사 페이지의 메타 태그**(제목·요약·분류·발행시각)만 읽는다. 본문은 안 가져온다. 요청 간격 2초, 수집기 이름을 밝힌 User-Agent.
- 시트는 **보는 용도의 사본**. 원본은 `news\data\news.db`. 시트 쓰기는 연결된 시트 도구로 한다.

## 미해결·주의
- 시트 올리기는 **Claude 가 JSON 을 읽어 값을 직접 붙여 넣는 방식**이라 하루 수백 건이면 느리고 무겁다. 자동화하려면 다른 방법(구글 API 키, CSV 가져오기 등)이 필요 (미정).
- 메타 요약(`og:description`)은 제목이 앞에 붙고 HTML 코드가 두 번 들어 있다. 지금은 내보낼 때만 다듬는다(100자). DB 에는 원문 그대로.
- 일시 오류(HTTP 522)가 났다 → 같은 명령을 다시 돌리면 빠진 것만 받는다(링크가 고유 키).
- 한경 외 매체 날짜 지정 방법 미확인. 네이버 API 키는 발급을 보류(등록 화면 목록에 검색이 안 보임).
- 시트의 `hankyung` 탭은 11/01 한 날짜만. 다른 날짜를 넣을 때 탭을 어떻게 나눌지 미정.
