# 2026-11-05 News — 양질뉴스와목표

상세: [[2026-11-05-양질뉴스와목표-상세]] · 앞: [[2026-11-05-자동검토]] · 목표: [[Knowledge/주식비서-목표와구조]]

## 한 줄 요약
"뉴스가 너무 많다"는 사용자 고민에서 **양질 뉴스를 사건 단위로 뽑는 코드**(`quality.py`)를 만들고, **이데일리 수집기**를 추가했다. 이어 RSS 를 검토했고, 마지막에 사용자가 **프로젝트 목표를 "주식 비서"로 다시 잡았다**. 뉴스는 그 비서의 입력(시나리오 추론)이 된다.

## 한 일
- **양질 뉴스(`quality.py`):** 그날 평소(다른 날 중앙값)보다 급증한 단어가 함께 나오는 기사를 한 사건으로 묶고, 정책·속보·분류 점수로 대표 기사를 뽑는다. 종목형(종목분석·특징주·시황)과 자동 X 는 뺌. `review_news` 요약 파일 맨 위에 "양질 뉴스"로 들어감. 11/04 는 중간선거 50건 등 8개 사건.
- **다른 매체 조사:** 연합·뉴시스·서울경제는 사이트맵에 최신 2~3일치만 있고 날짜 지정 불가, 이데일리는 날짜별 사이트맵이 2010년부터 있어 가능. → 이데일리 선택.
- **이데일리 수집기(`collectors/edaily.py`)** 와 `run_news` 매체 선택(1 한경 / 2 이데일리 / 3 둘 다). 24건 표본, 6건 저장 시험 통과. **하루치 전체는 아직 안 받음**(11/04 에 6건만 DB 에 있음).
- **Apps Script 변경 2건**(날짜+매체 단위 자동 X 보호, 시트 날짜·시각 정렬)과 분류 규칙 보완(`연예`·`스포츠`·`문화.레저` 대분류, `[美특징주]` 제목). **재배포 전, 실제 동작 미확인.**
- **RSS 검토:** 한경 RSS 는 카테고리 피드 12개(각 50건), 전체(`all-news`)는 3시간치 → 2~3시간마다 받으면 사이트맵 규모. 이데일리 RSS 는 11/03 06:40 에서 멈춰 사용 불가. 앞서 "한경 RSS 는 3분의 1 이하"라고 한 건 피드를 2개만 본 **내 오판이라 정정**.
- 사용자가 "갈아엎고 RSS 로?" 제안 → 수집기 파일만 바꾸면 되므로 갈아엎을 필요 없다고 답함. 그 직후 **목표 재정립**.

## 결정 (이유)
- **목표를 주식 비서로 재정립**(사용자): 주가 수집·Surge·Daily·뉴스가 모두 부품. 뉴스는 이벤트(인물 방문·정책·유가·질병)에서 관련 종목을 추론해 보고서를 만드는 데 쓴다. **전부 코드로**(토큰 절약). → [[Knowledge/주식비서-목표와구조]]
- 수집 방식 판단 기준이 바뀜: 과거 소급보다 **최신성**(하루 몇 번 자동 수집)이 더 중요. RSS·사이트맵 중 목적에 맞게 고르면 된다.
- 지금까지 만든 것은 **버리지 않는다**: 수집기만 방식에 의존하고 DB·시트·규칙·양질 뉴스·검토는 그대로 쓴다.
- 이데일리는 사이트맵(날짜 지정), 한경은 사이트맵 유지 + 필요 시 RSS 추가. 연합·뉴시스·서울경제는 RSS/사이트맵으로 오늘부터 쌓는 방식(미착수).

## 미해결·주의
- Apps Script 새 버전 배포가 필요하다(날짜+매체 단위 표시, 정렬). 새 코드는 실제로 돌려 보지 못했고 `node` 가 없어 문법 검사도 못 함.
- 이데일리 하루치(약 680건, 약 29분)는 아직 안 받음. 이데일리 사이트맵에는 수정된 기사도 올라 요청 날짜에 이전 날짜 기사가 섞여 저장될 수 있다.
- 양질 뉴스 기준이 사용자 목표에 맞는지 **사용자 검증을 아직 못 받음**. 사건이 쪼개지거나(같은 정치 사건이 둘로) 행사 시리즈가 끼는 한계, 비교할 날이 적어 여러 날 이어진 사건(바이낸스 해킹)이 약하게 잡히는 한계가 있다.
- 비서 구조는 **제안 단계**이고 사용자 확정 전. 정해야 할 4가지(보고서 주기, 종목 범위, 지식표 만드는 방식, 일정 범위)는 [[Knowledge/주식비서-목표와구조]] 참고.
