# 2026-11-05 News 시트연결 — 상세

요약: [[2026-11-05-시트연결]]

## 대화 흐름
1. 사용자: "스프레드 연결 다시 하려는데, 아까 만든 긴 문자열은 뭔지 기억도 안 나고 4번에서 막혔어". 4번은 "웹 앱으로 배포" 단계.
2. Claude: 토큰은 새로 만들면 된다고 하고, `news\.env` 를 만들어 임의 토큰을 넣었다. 처음에 `.env` 가 이미 있는지 먼저 확인하는 스크립트로 처리했고, 출력에서는 값을 가렸다(`SHEETS_TOKEN=(값 있음)`). 사용자가 메모장으로 `.env` 를 열어 토큰만 복사해 Apps Script 속성 `TOKEN` 에 넣도록 안내.
3. 사용자: "이건 따로 저장 안 해?" → 저장 위치는 `.env` 와 Apps Script 속성 두 곳, 볼트에는 값을 적지 않는다(볼트는 git 으로 GitHub 에 올라가므로)고 설명.
4. 사용자가 화면을 보냄: Google 로그인 팝업 "Google hasn't verified this app" (개발자 이메일이 본인 계정). 본인 스크립트라 나오는 정상 경고라고 안내. `Advanced` → `Go to (프로젝트) (unsafe)` → `Allow`. `BACK TO SAFETY` 는 누르지 않음.
5. 사용자: "배포까지 끝났어". `.env` 에 웹앱 주소 칸이 채워졌는지 형식만 확인(`https://script.google.com/macros/s/.../exec` 형태, `configured: True`).
6. 시험: `python run_news.py --from 2026-11-01 --yes` → 구글 시트 저장 단계에서 "0건 추가, 이미 있어서 건너뜀 179건". 토큰이 맞고 웹앱이 응답하며 링크 기준 중복 방지가 동작한다는 뜻. (시트는 이미 179건이 있어서 아무것도 바뀌지 않음)
7. 사용자: "근데 지금 수집 프로그램이 돌고 있어". 확인 결과 `python run_news.py` 프로세스가 오후 1:39 에 시작해 실행 중이었고 `news.db` 가 1:49 에도 갱신 중. `hankyung-2026-11-02.csv` 가 오후 1:25 에 만들어져 있었다(사용자가 앞서 돌린 것으로 보임, 어느 날짜까지인지 미확인). Claude 의 시험은 새 기사 0건이라 DB 에 쓰지 않아 충돌 없음.
8. 사용자: "여기까지 내용 기록해줘".

## 알아 둘 점
- `.env` 에 있는 값: `SHEETS_WEBAPP_URL`(웹앱 주소), `SHEETS_TOKEN`(토큰). Apps Script 스크립트 속성: `TOKEN`(같은 값), `SHEET_ID`(시트 주소의 `/d/` 와 `/edit` 사이). 값은 어디에도 적지 않는다.
- 동시 실행 주의: `run_news.bat` 두 개를 동시에 돌리면 sqlite 기본 대기 시간(약 5초) 안에 잠금이 안 풀려 `database is locked` 로 기사 일부가 실패할 수 있다. 수집기는 한 건씩 실패를 세고 계속하며, 같은 명령을 다시 돌리면 빠진 것만 받는다.
- 첫 실제 덧붙임은 사용자가 돌린 수집이 끝났을 때 처음 확인된다. 확인할 것: 시트 `hankyung` 탭에 새 행이 날짜 순으로 붙었는지, 날짜(`2026-11-02`)·시각(`06:52`)이 글자로 들어갔는지, 건수가 CSV 와 같은지.
