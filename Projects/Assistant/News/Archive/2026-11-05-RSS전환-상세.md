6. 사용자: "카카오 실적이면 실적 발표 시점·전분기 대비 정보가 있어야 하지 않나?" → 사건 기록 설계안과 DART 연계 제안. 사용자: "아니야 여기서는 뉴스 **수집**에 집중하자. 주식 종목에 직접 영향 있는 기사는 없었어?" → 키워드로 점검해 목록 제시.
7. 사용자: "응응 자연스럽게 찾아봐(태그), 미국에서 발행된 뉴스도 뽑아줘" → 태그 + 미국 RSS.
8. "CSV 날짜 고칠까요?" → "그걸 왜 고쳐"(급하지 않다고 설명) → "고쳐줘" → 최근 3일 제한, 옛 CSV 정리. "기록해줘" → News 폴더에 기록.

## 새 `classify.py` 규칙 요약
- 순서: [속보] 살림 → 제목 머리말 → (KEEP 단어 있으면 살림) → 약한 머리말·칼럼·군/구 지역 소식 → 분류 이름 → 제목의 무관 단어.
- 머리말 무조건 X: 포토·사진·부고·부음·인사·운세·날씨·카드뉴스·에세이·천자칼럼·취재수첩. 약한 머리말(영상·동정·게시판·책)은 KEEP 단어가 없을 때만.
- 제목 무관 단어: 연예, 스포츠, 사건사고, 부고·결혼, 생활·날씨. KEEP 은 주식·경제·정책·산업 단어 + 주요 대기업 이름 + 매각·이사회·드론 등.
- 시행착오: ① 파이낸셜 `사회|전국` 을 지역 소식으로 X 했다가 정책 기사가 걸려서 삭제(교육·건강 규칙도 삭제) ② `구속영장` 때문에 농협중앙회장 기사가 X → 삭제 ③ `이혼`이 연예로 걸려 삭제 ④ `기초연구` 가 "군·구" 규칙에 걸려 `연구` 제외 추가 ⑤ `장례` 때문에 상조사업 기사가 X → 삭제 ⑥ `시즌` 삭제 ⑦ 골프존홀딩스 매각 기사가 스포츠로 걸려 `매각|이사회|지분` KEEP 추가.
- 결과: 11/05 2,835건 중 197건(약 7%) X. 정답 라벨이 없어 정확도 숫자는 없음.

## 묶기(`cluster.py`) 설계
- 제목(과 요약 앞 120자의 0.3 가중치)을 단어별 글자 2개씩 자른 TF-IDF, 문서 빈도 20% 초과 2-gram 제외, 후보는 2-gram 3개 이상 공유한 쌍, 코사인 ≥ 0.30 이면 union-find 로 합침, 묶음 중심과의 유사도가 0.24 미만인 기사는 떼어 냄.
- 기준값 0.25/0.30/0.40 비교: 묶음 360/368/324개, 최대 묶음 98/64/37건. 0.30 사용.
- 11/05 상위: 카카오 실적 62건, 조작기소 특검법 59~64건, 코스피 출발 시황 54건, 가상자산 과세 유예 18~25건, 뉴욕증시·중간선거 15건, 한미동맹 반응 15건, 청해부대 14건, 넷마블 13건.

## 작업 중 실수·시행착오
- `mv db.py rss_placeholder` 를 잘못 넣어 `db.py` 가 이름이 바뀌고 이동 명령이 중간에 멈춤 → 사용자가 "잠깐"이라 해 멈췄고, 상태를 보고한 뒤 `src/db.py` 로 복구해 이동 마무리(데이터 손실 없음).
- 파이썬 코드 안의 줄바꿈 이스케이프가 쉘을 거치며 실제 줄바꿈이 돼 `run_news.py` 문법 오류가 세 번 반복 → 백슬래시를 `chr(92)` 로 만들어 해결. (`\\n` 이 `\r\n`/줄바꿈으로 바뀜.)
- `.env.example` 에 `printf >>` 로 덧붙이다 중복 → 파일을 다시 써서 정리.
- 스케줄 등록을 30분 → 1시간 → 30분 → 정각 기준 순으로 세 번 다시 등록(`Register-ScheduledTask -Force`).
- 9~10월 옛 CSV 가 미국 피드 때문에 생김 → 최근 3일만 쓰도록 `CSV_DAYS = 3`, 옛 CSV 삭제(DB 에서 재생성 가능).
