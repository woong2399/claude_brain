## 중요한 결정
- **수집은 RSS 전용(2026-11-05, 사용자 "갈아엎는다").** 이유: 자동 수집·최신성이 중요해서. 대가: 과거 날짜를 못 받는다. 아래 "웹 수집, 날짜 지정" 결정은 이것으로 **대체**됐다. 주기는 30분(속보 피드가 약 1시간 안에 밀려나서). 미국 기사는 한국어 규칙(X·묶기) 없이 태그 보고서에서만.
- 기사 원본은 볼트가 아니라 `news\data\news.db`(SQLite) 에 둔다. 볼트에는 기획·요약·공부 노트만. 이유: 기사가 하루 수백~수천 건이라 볼트가 무거워진다 (Daily·Surge 와 같은 방식). 옵시디언에서 기사 보기는 **나중에** (사용자).
- 수집은 **제목·요약·링크·시각만**, 본문은 필요할 때만 (RSS·검색 API 에는 본문이 없고, 스크래핑은 깨지기 쉽고 약관 문제가 있음).
- 처음엔 기사에 **종목을 붙이지 않는다.** 종목부터 끼워 맞추면 지금까지의 방식과 같아져서. 공시만 종목코드가 있다.
- 매일경제는 **네이버 검색 API** (사용자 선택, 구글 뉴스는 잘 안 쓴다고 함). Cloudflare 봇 차단은 우회하지 않는다.
- 미국 뉴스(중간선거 등)는 3단계 이후로 미룬다 (사용자: 2단계까지만).
- **웹 수집, 날짜 지정** (사용자). 사이트맵으로 링크를 받고 기사 페이지의 메타(제목·요약·분류·시각)만 읽는다. 본문은 안 가져온다. `robots.txt` 를 지키고 요청 간격 2초. 이유: RSS 는 건수·범위가 작고 날짜를 지정할 수 없다.
- **한경 먼저, 확인 후 확장.** 지금은 11/01 기사만 시험.
- 구글 시트는 보는 용도의 사본, 원본은 `news.db`.
- **X 달기는 규칙 1차 + Claude 검토**(사용자 선택). 확실히 무관한 것에만 달고, 주식·경제 단어가 있거나 [속보]면 안 단다(덜 다는 쪽). 사람이 표시·검토한 날짜(H·I열에 값)는 자동으로 덮어쓰지 않는다. 실행 파일은 수집(`run_news.bat`)과 검토(`review_news.bat`)를 분리.
- **목표 재정립(2026-11-05, 사용자):** 이 프로젝트는 주식 비서의 한 부품. 뉴스로 앞으로의 시나리오(젠슨 황 방한→반도체, 정책→관련 종목, 유가→정유, 조류독감→방역)를 추론해 보고서를 만든다. **전부 코드로**(토큰 절약), AI 는 규칙이 못 알아본 새 이벤트 분류에만. 지금까지 만든 것은 버리지 않는다(수집기만 방식에 의존).
- **수집 판단 기준 변경:** 과거 소급보다 **최신성**이 중요. 한경·이데일리는 사이트맵(날짜 지정), RSS 는 한경 가능·이데일리 불가. 이데일리 사이트맵 날짜는 발행시각 기준으로 저장.
- **양질 뉴스는 사건 단위**로 뽑는다(`quality.py`). 종목형(종목분석·특징주·시황)은 뺀다(종목 찾기는 나중).
- 시트 저장은 **Apps Script 웹앱 방식**(설치·클라우드 설정 불필요, 사용자가 한 번 설정). 비밀값(토큰, 웹앱 주소)은 `news\.env` 와 Apps Script 속성에만 둔다. 탭은 `hankyung` 하나에 덧붙이고 링크로 중복을 막는다.
