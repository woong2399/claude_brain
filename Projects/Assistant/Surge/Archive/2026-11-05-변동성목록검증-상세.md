# 2026-11-05 Surge — 변동성 추적 목록 검증 (상세)

요약: [[2026-11-05-변동성목록검증]] · 지표 정리: [[변동성-수급-지표정리]]

## 1. 대화의 흐름
1. "혹시 분봉도 읽을 수 있나" → Storage 로컬 DB `minute_bar`(1분봉, 2025-10-01~, KRX 정규장 09:00~15:30, 원 가격, 거래대금 칸 없음)를 읽을 수 있음을 확인.
2. 어제(11/04) 거래대금 30위를 장 시작~마감 분 단위로 모니터링해 새로 들어온/빠진 종목 정리 → 일단 보기만(저장 안 함).
3. "그날 거래대금이 갑자기 튄 애들도 조회할 수 있어?" → 급증 조회 스크립트를 썼으나 Storage 수집 중이라 로컬 DB 가 잠겨 있어 실패. 사용자가 "수집이 끝났으니 분봉을 봐도 돼" 해서 이후 실행.
4. 사용자 전략 설명: 거래대금 상위 몇 위까지 계속 기록해 들어오고 빠진 종목으로 수급 유입·이탈을 판단하고 싶다, 기준 순위 검증이 필요하다.
5. "일봉 기준이니 마더덕울 참고" → 마더덕 `storage.daily` 로 검증 시작 (분봉 불필요).
6. 진입 기준 분석 후, 사용자가 "**매수 조건이 아니라 변동성에 기준을 둬야 한다. 그 종목들을 추려서 추적할 것**" 이라고 정정 → 평가 기준을 적중률·포착률·목록 크기로 바꿈.
7. "거래대금 순위로는 못 봐?" → 순위만으로 범위·순위 급상승 변형을 다시 비교.
8. 순위 기준 목록과 가격·이력 기준 목록의 합집합 검증.
9. "수집이 끝났으니 분봉을 봐도 돼" → 분봉 급증 검증(1번 선택).
10. "수급이 들어왔다고 판단될 만한 지표로도 모자라?" → 보유 데이터 확인 후 지표를 A·B·C 로 정리, 그리고 기록.

## 6. 시행착오·오류
- `spike.py` 첫 실행이 `IOException: ... 다른 프로세스가 파일을 사용 중` 으로 실패: Storage 수집 프로세스(python PID 5088·3556, 18:57 시작)가 로컬 DB 를 잡고 있음. 프로세스를 끄지 않고 수집 종료를 기다렸다.
- 마더덕 쿼리에서 `select '...' name, *` 가 `syntax error at or near "name"` → `as nm` 으로 별칭 지정해 해결.
- 앞서 PowerShell `-c` 로 파이썬을 넘기면 따옴표가 깨져서 스크립트는 scratchpad 파일로 만들어 실행.
- 분봉 월별 처리(월 단위 임시 테이블 + `range between interval 30 minutes preceding and interval 1 minute preceding`)로 1.7억 행을 약 66초에 처리.

## 7. 데이터·방법의 한계
- 분봉은 수정주가가 아닌 원 가격이라 액면분할 등에서 튈 수 있다. 분봉 기준선(내일 +10%↑ 2.38%)이 일봉(1.42%)보다 높은 이유는 미확인.
- 분봉 거래대금은 추정값. 일봉 `amount` 는 2026-09-14부터 에프터마켓 포함.
- 적중률은 종목-일 단위 평균이라 연속 상한가 등 중복의 영향이 있을 수 있음(미확인).
- 상장폐지 종목 포함 여부 미확인, 비용·슬리피지 없음, 다수 조건을 시험해서 우연히 좋은 칸 존재 가능.
- Storage 에는 투자자별 순매수·체결강도·공매도·프로그램매매가 없다 → 진짜 수급 판단은 불가.
