## 결정 (이유)
- **날짜별로 JSON 한 파일씩**: 한 종목에 뉴스가 여러 개 붙는 구조라 CSV 보다 JSON 이 자연스럽고, 대시보드가 그 날짜 파일 하나만 읽으면 되어서 (사용자가 "날짜별로 저장할 거고"라고 정함).
- **코드는 글자(`"004545"`)**: 숫자로 저장되면 앞자리 0 이 사라짐.
- **Surge 10%↑ 와 텔레그램에만 있는 종목을 함께 담고 `source`(surge/telegram/both)로 구분**: 화면에서 거를 수 있게.
- **옵시디언은 나중에 활용**: 사용자가 "일단 옵시디언은 나중에 활용할게"라고 함. 이번 작업은 옵시디언 일지를 건드리지 않음.
- **역할 나누기**: 대시보드 코드(`app.py`)는 Assistant 세션만 고치고, Daily 는 `daily_data\data\날짜.json` 만 만든다 ([[Knowledge/주식비서-클라우드화면]]). 같은 파일을 두 세션이 고치면 충돌해서.

- **11/03~11/05 의 뉴스·테마는 비어 있음.** 시트에 11/03 테마·뉴스가 없고, 11/04·11/05 는 시트에 행 자체가 없음.
- **11/02 시트의 문제는 JSON 에 그대로 반영**: 한진칼우에 밀려 들어간 테마(`조선기자재, 피팅(관이음쇠) · 밸브`), 테마 칸이 빈 종목. 더블유씨피 오타 `전력저자장치(ESS)` 는 사용자가 옵시디언에서 고친 값으로 바꿔서 넣음.

- **텔레그램 가져오기는 수동**: `daily_data` 에서 `py build_daily_json.py` 를 실행해야 갱신됨. 올리기도 수동 (`py C:\Users\Jinwo\Documents\assistant\src\load_daily.py --since 날짜`).
