- 종가·거래대금 기준 점검: 등락률의 종가는 **정규장 종가**(Storage 문서 기준, 직접 대조는 미확인). `amount` 는 KRX 일봉 거래대금이라 2026-09-14부터 **애프터마켓이 섞여 있다**.
- 정규장 거래대금을 얻는 방법 조사: ① 로컬 분봉 합산 추정(`minute_bar_amount`, (시가+고가+저가+종가)/4×거래량) ② KRX 공식값 `krx_daily`(비어 있음, API 키 필요) ③ 그대로 둠.

- Storage 수집 시각 확인: 작업 스케줄러 `storage_update_1600`·`storage_update_2100` 이 평일(월~금) 16:00·21:00 에 켜져 있고(첫 자동 실행은 11-04 16:00), 수집 뒤 `after_update.ps1` 이 MotherDuck 에 올린다. 정규장 일봉은 분봉으로 만들어 늦게 돌려도 같다.
- 매일 돌리는 스크립트 `surge_daily.py` 작성·시험: 그날 `storage.daily` 행이 1,000개 이상일 때만 `surge.main.picks` 의 그날 행을 지우고 다시 넣고, 날짜별 CSV 를 만든다. 11/03 로 다시 돌려 21종목 그대로(중복 없음), 휴장일(11/07)은 종료 코드 1 로 건너뜀을 확인.

## 결정 (이유)
- **거래대금은 일단 애프터마켓 포함 값 그대로 둔다** (사용자 결정). 분봉 추정은 근사치이고 분봉이 로컬 DB 에만 있어 번거롭기 때문. 필요해지면 `amount_reg_est` 컬럼 추가를 검토.
- **MotherDuck 별도 DB `surge`**: Daily 세션이 SQL 로 날짜별로 바로 조회할 수 있고, `storage` 에는 쓰지 않아 기존 결정을 지킨다.
- **기간 2026-11-01 이후만**: 사용자 결정. "일단" 이므로 나중에 넓힐 수 있다.
- 제외 규칙·필터는 **적용하지 않음** (아직 안 정함).

- **매일 데이터는 16:00 수집 값으로 만든다.** 사용자가 수집이 끝나면 "1600 끝났어"라고 알려 주면 Claude 가 스크립트를 돌린다 (사용자 결정). 이 경우 `amount` 는 애프터마켓이 거의 빠진 작은 값이라 11/02·11/03 (애프터 포함)과 기준이 다르다. 등락률은 정규장 종가라 같은 기준.
- **Storage 의 `after_update.ps1` 은 고치지 않고 별도 스크립트로 만든다** (사용자 결정). 다른 프로젝트 코드를 건드리지 않기 위해. 자동 연결은 첫 자동 수집이 정상인지 확인한 뒤에 다시 정한다.

- **애프터마켓 값은 만들지 않는다. 정규장 기준으로만 만든다** (사용자 결정). 21:00 수집 뒤 거래대금 갱신 단계도 하지 않는다. `surge_daily.py` 는 16:00 수집 뒤에만 돌린다.
- **거래대금은 사용자가 Storage 에서 다시 backfill 한다.** `picks`·CSV 의 `amount` 는 `storage.daily` 에서 복사한 값이라 자동으로 따라 바뀌지 않으므로, backfill 이 끝나면 이미 만든 날짜(11/02, 11/03, 이후 날짜)를 `surge_daily.py` 로 다시 돌려 `amount` 를 맞춘다. 종목 선정은 등락률 기준이라 바뀌지 않는다. 날짜가 많아지면 여러 날짜를 한 번에 돌리는 옵션을 추가한다. backfill 뒤 조건정의서의 "애프터마켓 포함" 주의 문구도 고친다.

- **[정정, 같은 날 나중] 스크립트가 바뀌었다.** `surge_daily.py` 가 MotherDuck 이 아니라 Storage 로컬 DuckDB(`data/storage.duckdb`)를 읽기 전용으로 읽고, 거래대금은 정규장 분봉 추정 `amount_est`(애프터 제외)로, 결과는 CSV 만 만든다 (MotherDuck 에 쓰지 않음). 사용자가 "맞아"로 확인. 그래서 위의 "거래대금 그대로 둔다"·"backfill 뒤 다시 돌린다"·MotherDuck `picks` 갱신은 **더 이상 현재 방식이 아니다**. `picks`(69행)는 옛 사본. 현재 기준은 [[Projects/Surge/docs/조건정의서]] 와 README.

- **Daily 가 Surge CSV 를 가져가는 방법이 정해졌다.** `00_Index.md` 기준으로 Daily 세션이 `csv_to_daily.py` 로 Surge 의 날짜별 CSV 를 일지로 바꿔 11/02·11/03 일지를 새로 만들었다. 그래서 Daily 가 MotherDuck `picks` 를 읽을 필요가 없다. Daily 쪽 내용은 직접 읽지 않았다 (미확인): 새 CSV 열 `amount_est` 와 맞는지 확인이 남았다.
