# 2026-11-04 Surge — 10%↑ 종목 picks 저장

`storage.daily` 를 조회해 2026-11-01 이후 전일 종가 대비 10% 이상 오른 종목 69건을 MotherDuck `surge.main.picks` 와 PC CSV 에 저장했다.

## 한 일
- `storage.daily` 구조·범위 점검 (12.4M 행, 1985~2026-11-03, 중복 없음).
- 저장 위치를 **MotherDuck 별도 DB** 로 정함. 컬럼은 날짜·종목코드·종목명·등락률, 이후 거래대금 추가.
- 기간을 "일단 2026-11-01부터" 로 정하고 `surge.main.picks` 생성 (11/02 48종목, 11/03 21종목).
- `C:\Users\Jinwo\Documents\surge\` 에 날짜별 CSV 저장: `2026년 11월 2일.csv`, `2026년 11월 3일.csv` (처음 만든 합본 `picks_2026-11-01.csv` 는 사용자 요청으로 지움).

- 종가·거래대금 기준 점검: 등락률의 종가는 **정규장 종가**(Storage 문서 기준, 직접 대조는 미확인). `amount` 는 KRX 일봉 거래대금이라 2026-09-14부터 **애프터마켓이 섞여 있다**.
- 정규장 거래대금을 얻는 방법 조사: ① 로컬 분봉 합산 추정(`minute_bar_amount`, (시가+고가+저가+종가)/4×거래량) ② KRX 공식값 `krx_daily`(비어 있음, API 키 필요) ③ 그대로 둠.

## 결정 (이유)
- **거래대금은 일단 애프터마켓 포함 값 그대로 둔다** (사용자 결정). 분봉 추정은 근사치이고 분봉이 로컬 DB 에만 있어 번거롭기 때문. 필요해지면 `amount_reg_est` 컬럼 추가를 검토.
- **MotherDuck 별도 DB `surge`**: Daily 세션이 SQL 로 날짜별로 바로 조회할 수 있고, `storage` 에는 쓰지 않아 기존 결정을 지킨다.
- **기간 2026-11-01 이후만**: 사용자 결정. "일단" 이므로 나중에 넓힐 수 있다.
- 제외 규칙·필터는 **적용하지 않음** (아직 안 정함).
