## 0. 채팅 Claude 에게 부탁

- MotherDuck 의 **`woong_stock` 데이터베이스만 조회**한다. **데이터를 바꾸거나 지우지 않는다.**
  - `query_rw` 같은 쓰기 도구는 쓰지 않는다.
  - 같은 계정의 `stocks` DB(예전 매매일지·메모)는 건드리지 않는다.
- KRX 정보데이터시스템(data.krx.co.kr)을 자동으로 대량 조회하지 않는다. 약관 위반으로 IP 가 차단된 적이 있다. KRX 데이터는 공식 Open API 로만 받는다.
- 숫자로 말한다. 성공 사례만 보지 말고, 같은 조건 전체(실패 포함)와 비교한다. 기준 대비 몇 배(lift)인지로 말한다.
- 답은 한국어로, 쉽게 풀어서 한다.

## 2. MotherDuck `woong_stock` 데이터 (분봉 제외)

| 테이블 | 내용 |
|---|---|
| `daily` | code, date, open, high, low, close, volume = **정규장 수정주가**. raw_close = 정규장 **원주가** 종가. amount = KRX 일봉 거래대금(**백만 원**) |
| `stocks` | code, name, market(KOSPI/KOSDAQ), kind(보통주/우선주), foreign, nxt, first_seen, last_seen, delisted |
| `kiwoom_mktcap` | code, date, kiwoom_list_shrs(상장주식수), kiwoom_close(정규장 종가), kiwoom_mktcap(원). **2026-11-02부터** 매일 쌓인다. 그날 거래가 없던 종목은 시가총액이 비어 있다 |
| `krx_daily` | KRX 시가총액·거래대금용. **아직 비어 있음** (KRX Open API 키 신청 예정) |

- `daily` 는 약 1,237만 행이고, 1985-01 부터 마지막 수집일까지 있다.
- 평일 저녁 수집이 끝나면 그날 것까지 올라온다.

**데이터 주의**
- **거래대금(amount)**
  - 대략 2000년대 초까지는 키움 환산 때문에 단위가 맞지 않는다. 쓰려면 **2005년 이후만** 쓴다.
  - 2026-09-14부터 KRX 에 애프터마켓(16:00~20:00)이 생겼다. 그래서 amount 에는 애프터마켓과 시간외 거래가 섞인다. 가격(daily 의 OHLC)은 정규장만이다.
- **과거 시가총액은 없다.** "거래대금 ÷ 시가총액"은 아직 계산할 수 없다.
- **상장폐지 종목이 없다.** 생존 편향이 있어서 결과가 실제보다 좋게 나온다.
- **2015-06-15 전에는 가격제한폭이 ±15%였다.** 그래서 아래 조건 캔들(고가 ≥ 전일 종가 ×1.15)이 거의 나오지 않는다. 분석은 2015-06 이후로 보는 게 맞다.
- **보정한 오류:** 키움 일봉 중 환산이 빠진 47건(2001-03-23, 2001-07-03 등)은 이미 고쳐 두었다.
- **남은 이상치**
  - 9종목은 1997~2004년 일부 9거래일의 수정주가가 다른 출처와 10배 다르다: 000040·001260·003060·004870·012170·025620·030350·032860·060900
  - 그 밖에 대한방직 1987-07-21, 한국알콜 1996-09-18, HLB 2002-04-01, SM Life Design(063440) 2001-11-28.

## 3. 사용자의 전략 정의

**조건 캔들 (키움 수식)**

```
avg(거래대금,1) >= 15000      -- 그날 거래대금 150억 원 이상 (amount 백만 원)
and C(1) * 1.15 <= H          -- 고가 >= 전일 종가 × 1.15
and L * 1.15 <= H             -- 고가 >= 저가 × 1.15
and O * 1.09 <= C             -- 종가 >= 시가 × 1.09
```

**상승 구간 (1차 상승)**
- 기본: 저점 L 에서 **60봉 안에** 고가가 2L 이상이면 상승 구간이다.
  - 저점: 그 사이 가장 낮은 저가
  - 고점: 저점 뒤 60봉 안의 최고 고가
  - 한 구간을 잡으면 고점 다음 봉부터 다시 찾는다.
- **2차 상승은 뺀다.** 직전 상승의 고점 뒤 120봉 안에서 시작했고, 저점이 직전 저점의 1.3배 이상이면 뺀다. 상승은 처음 시작한 지점이 기준이고, 내려갔다가 다시 오른 구간은 의미가 없다.
  - 예: 혜인은 2026-07-29 저점만 쓰고, 10-15 저점은 뺀다.
  - 예: 스피어는 2025-12-05 저점(7,050원)만 쓴다.
- **이평선 조건:** 저점부터 고점 사이에 종가가 120·240·480일선 **모두의 위**에 선 날이 있어야 한다. 이평선을 돌파하며 오르거나 처음부터 위에서 오른 상승만 쓴다.
  - 예: 나노팀 2026-07-30 은 이평선 아래에서만 올라 뺀다.
- 조건 캔들은 저점 20봉 전부터 고점까지에서 찾는다.
- 결과: 전체 상승 구간 20,389건 → 2차 상승 4,643건, 이평 아래 4,430건을 빼고 → 조건 캔들이 있는 1차 상승 구간 **3,801건**.

**원래 아이디어 (아직 검증 못 함)**
- 상승 초반이나 그 전의 장대양봉에서 **거래대금 ÷ 그날 시가총액** 비율을 구해 평균을 낸다.
- 나중에 그 비율의 캔들이 나오면 매수한다.

## 4. 연구 결과 요약 (에이전트 10개, 2026-11-01)

**표본과 기준**
- 2005~2026-08 의 조건 캔들 31,419건.
- 성공 = 그날 종가에 사서 60봉 안에 고가가 2배. **기준 성공률 8.5%.**

**결론**
- **조건 캔들만으로 사면 손해다.**
  - 진입 4가지 × 청산 8가지 = 32개 매매 조합이 모두 평균 손실이었다. 2020년만 플러스였다.
  - +100% 익절 / −25% 손절: 승률 27%, 평균 −3.7%.
  - 손익분기를 넘으려면 2배 도달률이 20%를 넘어야 한다.

**나은 근거: "이미 강하게 움직이는 종목의 캔들"** (두 기간 모두 같은 방향)

| 근거 | 성공률 | 기준 대비 (lift) |
|---|---|---|
| 52주(240봉) 신고가 돌파 | 11.1% | 1.30 |
| 이미 120·240·480일선 모두 위 | 10.7% | 1.25 |
| 240일선 대비 +60% 이상 위 | 12.8% | 1.50 |
| 240일선 횡보 → 상승 전환 | — | 1.25~1.37 |
| 직전 20봉 박스 폭 70% 이상 | 12.2% | 1.43 |
| 상한가 근처 마감(+29% 이상) | 11.0% | 1.28 |
| 직전 20봉에 조건 캔들 2개 이상 | 11.2% | 1.32 |
| 평소 거래대금(직전 60봉 평균) 300억 이상 | 11.0% | 1.29 |

**좋은 조합**
- 상한가 근처 + 52주 신고가 + 직전 20봉 조건 캔들 1개 이상: 15.6% (lift 1.83)
- 원주가 1~2천원 + 종가가 52주 고가의 90% 이상: 약 17% (lift 2.0)
- 머신러닝 상위 10%: 15.9%. 하지만 "240일선 대비 이격" 하나로도 같은 성능이 나왔다.

**예상과 반대였던 것**

| 가설 | lift |
|---|---|
| 바닥(52주 저점 근처) 캔들 | 0.43 |
| 그날 이평선을 돌파한 캔들 | 0.65~0.84 |
| 좁은 박스·변동성 수축(VCP) | 0.58~0.75 |
| 조용한 바닥 뒤 첫 대량 거래 | 0.68~0.75 |
| 거래대금 30~50배 폭증 | 0.62~0.68 |

- 시장 분위기는 거의 효과가 없었다.

**쓸 만한 것**
- 다음날 종가가 조건 캔들 시가 아래로 내려가면 그 뒤 실패율이 91%였다. 사기 전 필터가 아니라 **손절 규칙**으로 쓴다.

**주의**
- 위 근거들로 2배 확률이 오르면 손실 위험도 같이 커진다. 60봉 뒤 수익률 중앙값은 더 나빠진다.
- 여러 조건을 한꺼번에 시험했으니 lift 1.1~1.2 정도는 우연일 수 있다.

## 6. 조회 예시 (MotherDuck SQL)

```sql
-- 최근 20일 일봉
SELECT d.date, d.open, d.high, d.low, d.close, d.volume, d.amount
FROM woong_stock.main.daily d JOIN woong_stock.main.stocks s USING (code)
WHERE s.name = '삼성전자' ORDER BY d.date DESC LIMIT 20;

-- 조건 캔들
WITH b AS (SELECT *, lag(close) OVER (PARTITION BY code ORDER BY date) AS prev_close FROM woong_stock.main.daily)
SELECT code, date, open, high, low, close, amount FROM b
WHERE date >= '2015-06-15' AND amount >= 15000 AND high >= prev_close * 1.15
  AND high >= low * 1.15 AND close >= open * 1.09
ORDER BY date DESC LIMIT 50;
```
