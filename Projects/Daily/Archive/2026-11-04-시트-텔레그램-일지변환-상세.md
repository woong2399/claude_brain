# 상세 기록

## 대화의 흐름
1. **설명**: 사용자가 찾는 것은 "뉴스 헤드라인, 링크"이고, 주식이 왜 오르는지 아직 잘 몰라 텔레그램을 참고한다고 설명. 텔레그램 내용도 일지에 넣고 싶으니 어떻게 쓰면 보기 좋을지 추천을 요청.
2. **추천(제안만)**: 시트 열을 `테마 / 텔레그램 / 헤드라인 / 링크 / 내 메모(선택)` 로 나누고, 일지에는 한 줄 안에 `<br>` 로 `텔레그램:`, `뉴스:`, `메모:` 를 이어 쓰자. 이유: 출처를 칸으로 나눠야 나중에 걸러 보기 쉽고, 텔레그램은 원문 그대로 두는 게 비교하기 좋음. 실제로 만든 것은 `텔레그램` 열 하나뿐 (`내 메모` 열과 헤드라인·링크 열 재배치는 하지 않음).
3. **11/02 텔레그램 글을 붙여 줌**(42종목) + "시트에는 내가 찾아보고 쓸만한 건 해놨어. 11월 2일만 한번 업데이트 해줘봐". 시트를 읽어 보니 사용자가 11/02 에 테마·헤드라인·링크를 일부 채워 둠.
4. **링크 요구**: "링크는 지저분하게 안 보였으면 해" → `[헤드라인](링크)` 형식과 `utm_*` 제거.
5. **시험 실행(파일 쓰지 않음)**: 11/02 시트 55행과 텔레그램 42종목을 코드로 맞춤 → 40개 일치, 텔레그램에만 있는 2개(영광, 씨케이솔루션), 시트에만 있는 15개. 이상한 점들을 보고: 더블유씨피 테마 오타, 한진칼우 테마 밀림, 하단 7행의 코드·등락률 문제, 테마 칸이 빈 8종목. 적용 전에 일지가 직접 고친 줄이 없는지 확인(48줄 모두 처음 생성된 모양).
6. **적용**: 일지 11/02 다시 씀(55줄), 종목 노트 +7, 테마 노트 +14. 사용자가 "시트에도 넣기"를 고름 → `H열 텔레그램` 추가 (H1 머리글, H2:H56).
7. **11/03 텔레그램 글을 붙여 줌**(17종목, 설명 없이 붙임) → 같은 처리: 시트 11/03 은 21행(테마·뉴스 비어 있음), 13개 일치, 텔레그램에만 있는 4개. 일지 11/03 을 다시 쓰고 H58:H78 에 텔레그램을 넣음. 읽어서 칸 정렬 확인.
8. **형식 요구**: "종목 / 뉴스 / 텔레그램 이 순서대로 해주고, 비어있는 종목도 두 칸 띄우고 정리해줘" → 줄 순서를 종목 → 뉴스 → 텔레그램으로 바꾸고, 비어도 `뉴스: `, `텔레그램: ` 칸을 남김.
9. **들여쓰기 요구**: "보기 쉽게 뉴스 텔레그램은 들여쓰기도 돼?" → em 공백(U+2003) 두 칸. 적용 전 비교에서 11/02 한 줄(큐리오시스)이 달랐음. 사용자가 그 줄에 공백으로 들여쓰기를 시험한 것(14:26 수정)으로 보여 공백 차이만 확인하고 덮어씀.
10. "오케이 기록해줘" → 이 기록. 위치는 Daily 로 진행.

## 줄 형식이 이번에 바뀐 과정

|---|---|---|
| csv_to_daily 가 만든 것 | `- [[Null]] \|\| [[종목(코드)]] +n%<br><br>` | 초기 생성 |
| 1 | `…+n%<br>텔레그램: …<br>뉴스: [헤드라인](링크)` | 텔레그램 추가, 링크는 문구로 |
| 2 | `…+n%<br>뉴스: …<br>텔레그램: …` + 빈 칸 유지 | 사용자가 순서 지정 |
| 확정 | 위 줄 앞에 em 공백 두 칸 (`<br>  뉴스: …<br>  텔레그램: …`) | 보기 쉽게 들여쓰기 |

## 스크립트 (`code/sheet_to_journal.py`)
- 입력: `telegram_MMDD.txt`(텔레그램 글 그대로. 블록은 `이름 / (코드) / (+등락%) / 문장`), `sheet_MMDD.json`(시트의 그 날짜 행 배열 `[날짜, 코드, 종목, 등락률, 테마, 헤드라인, 링크]`). 둘 다 스크립트와 같은 폴더에 둔다.
- 실행: `py sheet_to_journal.py 2026-11-03` (시험: 보관함에 안 씀, 결과는 같은 폴더의 `journal_날짜.md`, `h_column_MMDD.json`, `report_MMDD.txt`) / `--apply` (일지 백업 후 쓰기, 없는 종목·테마 노트 만들기).
- 코드 보정: 숫자만이고 6자리 미만이면 앞에 0 을 채움 (`42660` → `042660`).
- 등락률이 비면 텔레그램의 등락률을 씀. 둘 다 없으면 등락률 없이 씀.
- 테마: 시트 `테마` 칸을 쉼표(`,`)로 나눔. 비면 `[[Null]]`. 테마 문자열은 텔레그램 문장에 있는지 검사해 불일치를 보고(앞 6글자 기준). 텔레그램에 종목이 없으면 "확인 불가"로 보고.
- 링크: `utm_*` 제거, 공백·괄호는 `%20`·`%28`·`%29` 로 바꿈. 헤드라인의 `[`·`]` 는 `(`·`)` 로 바꿈.
- 보고서 항목: 시트·텔레그램 일치 수, 한쪽에만 있는 종목, 코드 보정, 등락률 채움, 테마 불일치·확인 불가, "테마 칸이 비었는데 텔레그램이 테마를 언급".

## 시도했다 버린 것
- 텔레그램을 일지에 `텔레그램:` 먼저 쓰는 순서 (사용자가 뉴스 먼저로 바꿈).
- 뉴스·텔레그램이 없으면 줄에서 아예 뺌 (사용자가 빈 칸을 남기라고 함).
- 일반 공백·`&emsp;` 로 들여쓰기 (공백은 화면에서 사라지고 엔티티는 소스에 보임 → em 공백 문자).
- 시트의 문제 셀을 직접 고치는 것 (사용자 데이터를 확인 없이 고치지 않기로 함).

## 주의
- 텔레그램은 Claude 가 읽을 수 없다. 글을 붙여 줘야 한다.
- 시트 값 읽기는 `get_values`(Google Sheets 커넥터)이고, 스크립트가 직접 읽지는 않는다 (Claude 가 값을 JSON 파일로 옮긴 뒤 스크립트를 돌림).
- 잘못된 테마 노트 `전력저자장치(ESS)` 는 시트 오타를 따라 만들어졌다. 시트를 고친 뒤 일지를 다시 만들면 일지는 맞아지지만 이 노트는 남으므로 따로 지워야 한다.
- 11/02 시트 하단 7행의 등락률 칸은 비어 있다.
