# 주식 비서 — 목표와 구조 (2026-11-05 재정립)

> 프로젝트 [[Projects/Storage/README|Storage]](주가 수집)·[[Projects/Assistant/Surge/README|Surge]](급등 종목)·[[Projects/Assistant/Daily/README|Daily]](일지)·[[Projects/Assistant/News/README|News]](뉴스)가 **모두 이 비서의 부품**이다. 결정 배경은 [[2026-11-05-양질뉴스와목표]].

## 목표 (사용자 말)
- 원래 하려던 것은 **주식 관련 내 비서**. 그래서 주가 데이터를 수집하고, Surge 를 만들고, 일지(Daily) 요약본을 쓰려는 것이다.
- **뉴스는 앞으로의 시나리오를 추론하는 데 쓴다.** 예: 젠슨 황이 방한한다 → 반도체 관련 소식이 있겠다 / 정부가 무엇을 추진한다 → 관련 종목 / 유가가 오른다 → 정유 / 철새 조류독감·돼지열병 → 방역 관련주.
- 이런 추론을 **보고서**로 만들고, **스케줄 관리**도 하며 총괄한다.
- **프로그램은 코드로** 한다. 이유: Claude 가 직접 읽고 판단하면 **토큰 사용량이 너무 많다**.

## 구조 (Claude 제안, 사용자 확정 전)
```
뉴스 수집 → 이벤트 추출 → 테마·종목 연결 → 검증 → 보고서
              └→ 일정(예정 이벤트) ──────────────┘
```
| 단계 | 내용 | 상태 |
|---|---|---|
| 수집 | 매체별 기사 수집 | **RSS 35개 피드(한국 10개 매체)+미국 7개 매체, 30분마다 자동**(2026-11-05, [[2026-11-05-RSS전환]]). 이데일리는 RSS 없음 |
| 이벤트 추출 | 기사에서 이벤트 종류(인물 방문, 정책 발표, 가격 변동, 질병 발생, 실적·계약 등)와 **날짜**를 규칙으로 뽑음 | 같은 사건 묶기(`events.py`)와 종류 태그(`tags.py`)까지. 사건 기록(발표 시점·수치)은 보류 |
| 지식표 | 이벤트·키워드 → 테마 → 종목 연결. 사용자가 고치는 파일. **핵심 자산** | 없음 |
| 검증 | 연결이 실제 주가에 맞았는지 Surge·일봉으로 확인해 점수 반영 | 데이터는 있고 연결은 없음 |
| 보고서 | 아침/장마감 후 보고서를 **템플릿으로 생성**(오늘의 사건, 예정 일정, 관련 테마·종목과 근거) | 없음 |
| 일정 | 뉴스에서 뽑은 예정 이벤트를 달력으로 | 없음 |
| 자동 실행 | 작업 스케줄러로 수집 → 검토 → 보고서 | 없음 |

## 토큰 정책
- 기본은 **AI 없이 전부 코드**(규칙, 사전, 통계, 템플릿).
- AI 는 **규칙이 못 알아본 새 이벤트를 분류할 때만** 쓰고, 결과를 저장해 같은 질문을 반복하지 않는다. 하루 호출 상한을 둔다.
- 지식표 갱신은 사용자와 Claude 가 가끔 같이 하는 작업이다(매일 돌리는 부분이 아님).

## 핵심 아이디어: 급등 종목 ↔ 같은 날 뉴스 자동 연결
Surge 의 10%↑ 종목에서 종목명·사업 키워드가 뉴스에 나오면 "이 이벤트 때문에 올랐다" 후보가 코드로 쌓인다. 지식표를 처음부터 사람이 쓰지 않고 **제안받아 승인**하는 방식으로 키울 수 있다. 사용자가 중간선거 때 말한 "예전 정책 → 업종이 움직임" 학습이 이렇게 쌓인다.

## 주의
- 추론은 **예측이 아니라 "근거 있는 후보 목록"**이다. 보고서에는 어떤 기사 때문에, 어떤 연결로, 과거에 몇 번 맞았는지를 같이 적는다.
- 정확도는 **지식표의 질**에 달렸다. 처음엔 연결이 거칠고 틀린 후보가 많다.
- 일지(Daily)는 **직접 타이핑**하는 것이 사용자 취향이다([[사용자]]). 이 보고서는 일지를 대체하는 것이 아니라 별개의 자동 보고서다. 헷갈리지 말 것.
- 사용자 개인 도구 설계이고 매수·매도 권유 도구가 아니다.
